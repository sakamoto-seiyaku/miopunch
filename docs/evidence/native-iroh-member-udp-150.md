# MIOPUNCH-150 原连接增强 UDP 验收

两个真实已准入的成员先经获准 HTTP relay 建立原生融合连接和双向业务流。轮次触发端由测试选择，原 QUIC client 始终是 A。两端用同一个受保护轮号分别读回实际首个匹配包、胜出 socket、原路径新鲜 ACK 和原业务流的新字节。服务在各端核对实际序号。两个读取证明都必须来自选中路径上的同一原流，接收计划的一端才结算一次。

[验收入口](../../scripts/check_member_fusion_nat.py)复用[两网关命名空间拓扑](../../scripts/nat4_irregular_lab.sh)。使用两个真实 STUN 目的地和原有 frp 角色表。固定组用 5 秒调用上限。同方向正例与阻断组共用规则和包数上限，阻断仅丢弃横跨两个 WAN 地址的准备方回程。接收方看到的原始 UDP 包来源分别为 `100.64.27.6:43037` 和 `100.64.27.2:42037`，而两个观察点报告发送方端口 `43027` 和 `42027`。原连接验证使用前两个实际来源。

| 固定组触发端 | 回程 | A 耗时 / 包数 | B 耗时 / 包数 | 结果 |
| --- | --- | ---: | ---: | --- |
| A | 通 | 622 ms / 5 | 623 ms / 2 | 双端原流往返，B 记一次成功 |
| B | 通 | 602 ms / 2 | 601 ms / 5 | 双端原流往返，A 记一次成功 |
| A | 丢弃 | 4991 ms / 5 | 4992 ms / 48 | A 收到请求，B 未收到回包，原流保留在 relay |
| B | 丢弃 | 4992 ms / 48 | 4991 ms / 5 | B 收到请求，A 未收到回包，原流保留在 relay |

随机组两方向使用相同拓扑、观察映射、打法 `4/0` 和 38 秒调用上限。A 的两个观察端口为 42040 和 42080，B 的观察端口为 43028 和 43030。A 绑定 256 个临时监听端口，防火墙在每轮屏蔽 B 到 A 的主端口和两个观察端口。记录本端发出的原始请求和回复数，耗时从本端计划执行起计，预算从调用起计。两端各自使用原期限，受保护协商耗时占用该期限。

| 随机组触发端 | 样本 | A 耗时 / 包数 | B 耗时 / 包数 | 结果 |
| --- | ---: | ---: | ---: | --- |
| A | 1/2 | 10652 ms / 1288 | 10653 ms / 300 | 原流往返 |
| A | 2/2 | 12714 ms / 1288 | 12715 ms / 457 | 原流往返 |
| B | 1/2 | 10642 ms / 1288 | 8021 ms / 324 | 原流往返 |
| B | 2/2 | 12663 ms / 1288 | 10024 ms / 519 | 原流往返 |

方向 A 为 2/2，方向 B 为 2/2，各无未命中。四轮的实际胜出 socket 均为 A 的临时监听端口，各自保留 1 个，其他 255 个逐一重新绑定验证释放。另做每向一次受控回程丢弃，不纳入自然样本。A 仍有实际匹配包，两端继续由 relay 完成同一原流往返，均未验证或结算增强路径。A 的 256 个临时端口全部可重新绑定。

| 随机阻断触发端 | A 耗时 / 包数 | B 耗时 / 包数 |
| --- | ---: | ---: |
| A | 37992 ms / 1288 | 37994 ms / 1486 |
| B | 37993 ms / 1288 | 35315 ms / 1486 |

原始双端日志、内核转发规则计数和逐轮结果在 `/tmp/miopunch-150-lab-run2/`。该矩阵执行后，候选接入现有暂存 QUIC 路径的取消所有权。用固化二进制复验固定正反均通过。新增的两向阻断保留两个方向的原始探测包，只丢弃 QUIC 回程。双方均独立读回实际匹配包和各自的胜出绑定，均无新鲜 ACK、业务结算或学习，原流继续走健康 relay。结果位于 `/tmp/miopunch-150-final-nat/`。

暂存路径更新后的首个临时端口复验与其他回归并行。B 完成同流确认并计分，随后等待下一条原流请求时达到既有 6 秒期限，A 的日志在运行器回收前没有终态。保留该次两端原始日志。独立复验沿用同一原流检查和两端期限。A 与 B 分别于 10653 和 10654 ms 完成，A 实际保留 socket 6（本地端口 37780），255 个其余端口释放。两次均独立于上表预先固定的自然样本。原始记录见 `/tmp/miopunch-150-final-nat/random-a-1/` 与 `/tmp/miopunch-150-temp-diagnosis/random-a-1/`。

旧混合观察用例曾在 QAD 建连时耗尽默认测试线程的栈。流接收观测改为在实际启用时分配，首包记录留在融合轮次，旧执行账本保持原布局。同一旧入口和融合原流测试均通过，见 `/tmp/miopunch-150-stack-fix/`。

在随机组的同一阻断拓扑中，测试等对端实际发包后取消原调用。修订前 A 取消后 B 从 4 包继续到 155 包，触发 2 秒断言时原期限仍余 30.35 秒。修订后 A 取消时，B 从 4 包停在 5 包，原期限尚余 32.35 秒。B 取消时，A 从 3 包停在 4 包，原期限尚余 35.35 秒，256 个临时端口全部可重新绑定。两向的原 relay 流都继续往返，双方及时释放轮次名额，通过在同一原连接上达成下一份计划验证，且均未结算成功。随后固定正反向复验均通过。日志见 `/tmp/miopunch-150-peer-cancel-red/` 和 `/tmp/miopunch-150-peer-cancel-green2/`。

WASM 构建保持 157 基点的两条错误。共享调用处缺少 `noq_proto`，浏览器调用 `improve_existing` 缺少第七个参数。办公网及热点的 `8ab55370` WAN 回程仍未知，见[现场记录](network-demo-140-2026-11-18.md#1058-手动重连与增强打洞回程)。
