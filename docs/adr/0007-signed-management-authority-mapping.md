# 将创世权限映射为独立签名作者，并在因果前态校验管理动作

2026-09-29，接受为 MIOPUNCH-23 的管理记录接线基线。领域行为仍以 [MIOPUNCH-14 父规格](http://192.168.4.22:2080/work/projects/aa58cd82-2afc-404b-a097-58ef553c7ca4/issues/4700bf29-2a4e-40bc-93fe-7f5148207189)及已接受的 Plane 决议为准；本 ADR 固定实现映射，不扩充成员产品范围。

网络身份取独立 Ed25519 创世凭证的公钥。每台设备使用不同的节点密钥；创世公钥作为 p2panda-auth 组 ID 和虚拟 `Manage` 成员，仅用于签署高权限记录，不代表在线设备或应参与秘密轮换确认的成员。一个网络视图还钉住由该根签署、包含虚拟根和首台设备管理员的 canonical `Create` 操作哈希；另一条 `Create` 即使由同一根签署，也不能替换已钉住的创世记录。同一凭证在新设备恢复时保留网络身份及原有管理员状态，新凭证对应新网络。

签名管理头的版本、组 ID、类型化动作、因果依赖和每作者日志 ID 都在 p2panda-core 的 Ed25519 签名内。此阶段用 `Access::Read` 表示普通成员、`Access::Manage` 表示日常管理员，限制条件和子组不进入该映射。日常管理员可添加、移除普通成员；管理员任免、移除仍具管理员资格的设备及管理员自退出须由创世作者签名。创世作者不能删除自己的虚拟成员。授权校验使用 p2panda-auth 在操作依赖处重建的真实因果前态，保留原有 StrongRemove 并发过滤规则，不把本机当前视图或 UI 状态当成记录权限依据。

作者日志按 `(签名公钥, 128 位日志 ID)` 区分并检查连续 `seq_num` 与 `backlink`。同一日志的上一条记录还必须出现在新记录签名依赖的因果祖先中，避免实际先后发生的管理动作被 StrongRemove 误判为并发。恢复了同一创世密钥的新设备须使用新的随机日志 ID，从序号零开始，不依赖旧设备的日志尾；与原网络管理图的因果关系仍由签名依赖表达。后续持久化票负责随机 ID 的安全分配、日志状态提交及恢复。根权控制会话证明、canonical 创世历史的受限取得、数据库崩溃恢复和连接权限执行仍由后续票交付。

最小上游改动、双到达序实测结果及复现命令见 [MIOPUNCH-23 验证记录](../notes/2026-09-29-management-auth-validation.md)。
