# 创世高权限操作逐项确认

2026-10-20，用户明确确认。创世高权限操作频率很低，但后果非常重要，因此每项操作都应针对具体动作、对象和影响单独验证确认，不采用一次解锁后可连续执行不同危险操作的通用提权窗口。浏览器、PWA 和安装版采用同样规则；普通入网审批等日常管理操作仍沿用已有权限分类；日常服务 ACL 修改已明确不需要创世确认，由具有相应权限的管理端或节点执行。

确认只覆盖本次操作的网络、动作、目标及关键参数；这些内容发生影响授权含义的变化时，应重新确认。同一已确认操作的网络重试、续办或结果查询沿用该次操作及已提交结果，不反复打扰用户，也不重复执行或产生另一项授权；执行仍须核对当前权限和操作有效性。逐项确认不要求把一个操作的底层消息或签名步骤分别变成用户弹窗，具体操作边界、有效期和恢复接线仍需设计。

用户进一步确认重要操作的默认交互：从当前设备发起，在已有凭证的设备上核对并确认具体操作，本机持有时就在本机确认；凭证在另一台设备时，由该保管设备确认并回传结果，不因确认而复制创世凭证到发起端。无法走通这条流程时，再使用恢复卡等离线凭证方式；不要求用户每次选择凭证来源或先做导出、复制、临时导入。两条路径都只确认同一项具体操作，离线凭证方式不提供通用提权窗口。

本决定取代原有面向用户的 sudo 式临时提权窗口语义。当前 Native／Browser SDK 仍使用会话窗口，签名与权限校验的已有实现及历史验证记录保留；本轮只记录新设计，尚未修改运行代码或实现跨设备确认协议。讨论记录见[日常使用与后续流程](../notes/2026-10-03-shared-web-client-ui-direction.md)。
