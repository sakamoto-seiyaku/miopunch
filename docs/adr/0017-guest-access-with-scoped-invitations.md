# 三种节点身份与专用来宾邀请

2026-10-20，用户确认初版的节点身份采用来宾、普通成员和管理员三种。来宾用于朋友临时传文件等有限用途，普通成员用于长期参与网络，管理员管理成员和服务访问规则；服务使用仍取决于有效授权和平台实际能力。创世凭证保管及逐项创世确认沿用既有规则，不增加第四种节点等级。

用户进一步确认默认访问方式：支持某项能力不等于已经开启；节点主动开启服务后，默认向本网成员开放，需要限制具体成员时修改同一套 ACL，来宾仅按专用邀请授予的范围访问。已有明确限制仍由当前有效规则执行，开启服务不能被当作隐式清除这些限制。服务访问资格不等于自动发起业务或全网广播内容；用户随后将剪贴板范围收敛为一对一，开启后自动同步，不采用此前讨论的分组同步。

来宾通过专用邀请链接或二维码接入，取得本次分享所需的临时服务访问资格，不因参与一次分享自动成为永久普通成员或获得其他服务权限。用户进一步确认首版每份来宾邀请仅接入一台来宾设备：首次成功接入后绑定其节点身份，在原分享授权仍有效时允许同一身份重试和重连，其他节点不能重复使用该邀请；邀请另一台设备需另发一份。临时分享可以包含对相关节点 ACL 的必要临时授权；具体授权由具备相应修改权限的节点完成，不表示一个发起端可以任意修改其他节点的 ACL。邀请的具体格式、有效期和完成后的结束条件、重新接入与撤销机制仍待细化。

生成来宾邀请时，选定涉及的节点、允许使用的服务和有效时间，形成该邀请的访问范围；这不是获得节点所有服务的通用资格。授权粒度沿用节点声明的服务，以“节点 → 服务”表达；不另加一套通用资源层级，具体服务如何表达自身能力留在相应模块中确定。日常服务权限修改由具有相应管理权限的管理员或节点执行，不需要创世确认，服务 ACL 仍按同一套规则处理。管理员任免等既有创世高权限操作继续沿用 ADR 0015。

用户确认来宾打开邀请后直接进入受邀功能页面，只呈现本次分享相关的对象、操作和有效时间，不进入完整网络设备列表、其他服务入口或管理界面。实际访问继续由 ACL 校验；界面隐藏不替代权限执行。该决定不单独承诺底层发现或授权验证所需元数据的完全隔离。

文件接收采用简单的身份区分：接收服务已开启且访问获准时，普通成员和管理员发来的文件默认自动接收；来宾发来的文件需要接收端确认后再接收。接收确认是本次文件传递的交互，不授予新的成员资格或扩大服务权限，也不需要创世确认；平台要求的文件保存授权继续适用。

用户进一步明确，管理员生成的来宾邀请可以带来宾资格有效期，例如一小时；到期自动终止该来宾成员资格并停止其访问，而不只是使尚未兑换的链接失效。一小时是用户给出的例子，尚未选定统一默认时长。用户确认采用一个简单截止时间：从创建邀请开始计时，邀请链接和来宾资格共用该截止时间，晚加入不会获得新的完整时长；不继续展开严格计时精度设计，也未另设宽限时长。用户确认主动退出会结束来宾资格，短暂网络中断可以在原有效期内重连，重连不延长有效期，到期自动清退。关闭应用或页面仍沿用断连与主动退出分开的既有语义。

节点可以管理自己对外声明的服务，并发起相应分享；管理员仍可远程管理访问规则，由目标节点验证执行。用户进一步确认，管理员的限制应被遵守，但管理员远程修改和节点本机修改面向同一套 ACL：限制直接体现在节点已验证并保存的有效规则中，临时分享遵守该规则，不另设管理员 ACL 与本机 ACL 的叠加优先级机制。当前按个人使用场景收敛，两处同时修改同一规则的并发冲突处理暂不展开；没有据此选择最后写入获胜、时间戳排序或任何冲突算法。

本决定扩展此前不支持临时成员的范围，既有普通邀请／precode 的到期语义保持独立：码过期限制新兑换，不会自动终止已授予的普通成员资格。现有运行代码尚未实现新的来宾身份和服务 ACL 模型，本轮只记录产品决定。讨论见[共享客户端记录](../notes/2026-10-03-shared-web-client-ui-direction.md)。
