# 保留原库契约与默认行为，新增策略显式选择

2026-10-13，用户在整体 fork 兼容性的 grill-with-docs 访谈中确认：尽量不改原库的既有接口与默认行为，原来默认启用的功能继续启用，使已有调用者尽量无需修改源码即可重新编译并正常运行。miopunch 的资源限制及其他产品策略通过新增接口或显式配置选择，不以产品策略改写普通库入口的默认行为。新增接口沿用已有 API 的设计思路；受限端点与连接交付的具体方向见 [ADR 0010](0010-preserve-upstream-early-data-interface.md)。

用户接受经过验证的通用缺陷修复继续保留，即使修复改变原运行行为；兼容目标不要求恢复已确认的缺陷。尚未证明普遍适用的变化应先补证据，再决定是否作为通用修复。当前 Backup ACK 调度属于待补证据项，不能因现有 demo 需要就直接认定适用于所有原消费者。

同日用户确认整体设计归纳准确，可作为规格基础：p2panda 保留旧错误类型，新检查采用独立错误类型；旧 selector 保留原调用语义，连接级选择采用新入口。原有 features 与产物纳入兼容核对。验收同时检查旧消费者尽量不改源码即可编译、正常运行，以及当前 demo 的安全约束与完整流程继续成立。

本决定规定后续兼容整理的取舍，没有实施默认值恢复或新的源码修改，也不扩大 [ADR 0009](0009-unified-session-and-capability-based-paths.md)中的产品应用协议兼容范围。
