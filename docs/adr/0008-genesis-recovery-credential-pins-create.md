# 创世恢复凭证同时固定根私钥与 canonical Create

2026-09-29，用户明确接受。恢复原网络所保存的原创世凭证由独立 Ed25519 根私钥和该网络唯一 canonical `Create` 操作哈希共同组成。两项须作为同一份可信备份取回；仅有根私钥而没有固定哈希，不足以声称已识别原网络的授权历史。这补足了 [ADR 0007](0007-signed-management-authority-mapping.md) 中已钉住网络视图的恢复入口，不更改网络身份仍由根公钥标识的规则。

恢复节点在真实受限连接上用根私钥证明权威，证明同时绑定固定 `Create` 哈希、双方经过 TLS 认证的节点身份和当前会话。持有普通成员资格的联系端先核对其自身已钉住的哈希，验证根权后才交付已应用的完整管理历史和当前准入秘密。恢复节点再次核对完整签名历史的 `Create` 哈希，再签出以自己节点身份为目标的根授权记录。相同根私钥签出的其他 `Create` 也不能替代备份所固定的原始历史；缺哈希、错哈希、错根或错目标均不能走此恢复入口。

根恢复凭证、每台设备的节点身份和网络共享准入秘密是三类独立材料。根凭证不充当普通在线成员，也不自动授予未验证连接业务访问；恢复不自动撤销原管理员。恢复证明的最窄实测入口及失败检查见 [MIOPUNCH-25 验证记录](../notes/2026-09-29-genesis-recovery-proof-validation.md)。实际备份介质、密钥保护和用户操作界面由后续交付决定；任何备份实现都必须完整、可信地保存上述两项。
