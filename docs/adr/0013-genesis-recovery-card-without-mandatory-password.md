# 创世恢复卡不强制额外密码，加密文件作为可选导出

2026-10-20，用户接受。日常由指定设备保护并使用创世凭证；独立恢复卡默认不要求再设置一套专用密码，引导用户打印后妥善保管，或存入自己的密码管理器。需要以普通电子文件保存时，提供可选的加密文件导出。此取舍避免把兜底恢复变成必须同时找齐文件和另一个密码；它不要求所有备份明文存放，也不取消设备自身或密码管理器提供的保护。

恢复卡完整承载 [ADR 0008](0008-genesis-recovery-credential-pins-create.md) 的根私钥与 canonical `Create` 哈希；二维码、文本或文件是承载形式，本身不提供加密。持有未额外加密的完整恢复卡即可取得创世权限材料，因此按最高权限秘密保管。恢复卡不包含管理历史或业务数据，找回凭证不等于这些内容已恢复；本决定不引入根副本单独撤销或更换根而保留原网络身份的能力。

同日用户进一步明确：**首次创建网络后必须先保存恢复卡，完成后才能进入正常使用**；不采用可跳过、稍后备份的首次流程。这一要求针对创建新网络，不自动要求普通受邀加入设备取得或备份创世凭证。保存后由用户确认已保存即可继续，不额外要求重新导入或扫码读回检查。

具体编码、保存确认交互、加密导出的格式与算法，以及 TOTP／扫码／节点弹窗如何接入仍待设计；本决定不启动实现。取舍依据与行业参照见[研究报告](../notes/2026-10-20-genesis-credential-backup-and-recovery-research.md)，讨论过程见[日常使用与备份体验](../notes/2026-10-03-shared-web-client-ui-direction.md)。
