# 换机迁移同一节点身份

2026-10-20，用户确认。将“新增设备”和“迁移本机”区分：新增设备使用独立节点身份并走既有加入流程；换机通过完整节点迁移保留同一逻辑节点身份、适用设置、授权历史和必要私有材料，已有创世凭证时一并迁移。普通成员、日常管理员与兼任创世凭证保管的节点共用一个迁移流程，权限依据仍有效的网络授权延续，避免用户分别重做入网、管理员任命和凭证交付。

迁移先暂停旧节点并准备一致的备份，安全交付到目标，恢复并确认成功后清理旧端本地材料。旧端停止使用该身份，不发布网络 Leave／Remove，否则同一身份在新端也会失去成员资格。需要两台设备同时使用时走新增设备流程；本决定不承诺两个身份副本可持续并行运行、无中断热切换或分区中的全局单端运行保证。失败与续办不得让新旧端无条件同时重开。

此处是同一节点更换运行设备，与 ADR 0006 的切换到另一个网络不同，也与仅凭创世恢复卡恢复最高权限不同。只有恢复卡而无完整节点备份时，不保证恢复原节点身份和设置。恢复旧快照不能撤销其后有效的成员移除或管理员降权，也不能信任已回滚的 precode 计数。

底层依据已核对：Iroh 1.2.0 以节点私钥对应的公钥作为 EndpointId；本项目将 p2panda-auth 的成员 ID 映射为节点公钥，管理动作以签名和有效历史校验。管理记录使用新的随机作者日志 ID，并保留因果依赖，避免重用旧日志序号；Native 的一致备份恢复已有保留节点 ID／网络锚的测试用例，恢复会停止旧 precode。此轮只检查代码，未重新运行测试。现有备份原语不自动完成旧端停用、跨设备安全交付或跨平台迁移；Browser／PWA 的逻辑导出导入、迁移包与失败处理仍待设计、实现和验证。本决定只记录产品语义，不启动运行代码实现。
