# Roadmap

## 文档状态

- 本文档用于收束前期讨论。
- 当前版本只定义主线，不锁死细节。
- 后续按实验结果、实现成本、真实网络表现持续调整。

## 定位

- `miopunch` 是一个以 `frp xtcp` 为起点、持续演进的 `Go NAT traversal` 项目。
- 项目关注 `可测试`、`可复现`、`可演进`。

## 核心目标

- 抽离一个最小可运行、可独立演进的 NAT traversal 内核。
- 在经典 UDP 打洞基础上补齐辅助连通性能力。
- 将“打洞成功”与“数据传输”解耦。
- 建立一套可复现的 NAT 测试与回归体系。

## 非目标

- 不在早期追求完整产品形态。
- 不在早期承诺完整虚拟局域网能力。
- 不在早期承诺 `TCP` 打洞、`VPP`、全平台完整支持。
- 不以 GUI、包装、易用性为当前重点。

## 开发原则

- `测试先行`。
- 追求尽可能完整的测试覆盖。
- 接受“测试代码多于功能代码”。
- 每个阶段都必须可验证、可演示、可回归。
- 优先解决真实 NAT 场景下的成功率、稳定性、可解释性。

## 测试体系

- 单元测试：协议、状态机、NAT 分类、重试、回退策略。
- 集成测试：基于容器或虚拟化的 NAT 拓扑回归。
- 真实环境验证：安卓蜂窝、本地宽带、云服务器组合验证。
- 核心指标：建链成功率、建链时延、吞吐、回退率、不同 NAT 组合表现。

## 主线 Roadmap

### P0 测试台先行

- 先建设 NAT 仿真与回归环境，再推进功能开发。
- 优先方案是 `netns + veth + nftables/iptables + tc`。
- `Docker in Docker`、`QEMU` 作为后续补充，而不是起点。
- 产出应包括可脚本化拓扑、回归用例、基础指标采集。

### P1 抽离 XTCP 内核

- 从 `frp xtcp` 提炼最小 NAT traversal 核心。
- 范围包括 `STUN`、NAT 分类、信息交换、`make hole`、`fallback`。
- 目标是形成可独立测试、可独立运行、可独立演进的核心库与最小 CLI。
- 这一阶段不引入复杂组网语义。

### P2 补齐连通性

- 在基础打洞流程上补齐 `UPnP`、`NAT-PMP`、`PCP`、`IPv6`、双栈策略。
- 将端口映射辅助视为连通性增强，而不是经典打洞的替代。
- 将 `IPv6` 视为一等公民能力，而不是附属特性。
- 目标是最大化真实网络中的建链成功率。

### P3 抽象传输层

- 将打洞成功后的 session 抽象成独立传输层接口。
- 默认优先 `QUIC`，后续接入 `KCP`。
- 在传输层稳定后，再评估 `HY2` 风格的调度与拥塞控制优化。
- 目标是把“能连上”与“传得好”拆成两个独立问题。

## 后续方向

- 个人 `overlay / mesh` 网络。
- 多节点互通、节点间转发、弱中心化 relay。
- `VPP` 数据平面。
- `TCP` 打洞。
- `udp2raw` 式伪装与用户态协议栈实验。
- `Linux / Android / Windows` 深化支持。

## 里程碑原则

- 每个阶段都必须有单独产出物。
- 每个阶段都必须定义回归基线。
- 每个阶段都必须用真实网络或仿真网络复验。
- 新方向进入主线前，先通过实验分支验证价值。
