# MioCube 跨设备协作讨论稿

2026-11-25，尚未定稿。本轮以自有设备为范围，参考 Apple 连续互通，日常操作沿用各平台惯用入口。现行产品基线见 [MioCube Context](../../CONTEXT.md)。

## 日常协作

- **剪贴板**在多台已授权设备之间接力，支持纯文本、HTML、图片和文件。复制时静默通知对端，粘贴时按需取，只保留短时有效的当前内容。Android 默认用平台分享等显式入口，后台读取可评估 Shizuku。
- **文件传输**从系统分享或文件管理器发起，也可把文件拖入明确的分享界面。用户选目标，自有设备自动接收。MioCube 显示进度、结果和保存位置，文件可从系统惯用位置打开。
- **键鼠接力**按屏幕排列跨边缘切换，键盘跟随指针。设备锁屏或睡眠时断开，恢复可用后可重连。
- **文件夹与磁盘映射**让另一台设备以路径或盘符访问共享目录，保存写回原处。可独立使用，也可配合串流。

## 串流与外设

- **屏幕共享**接到对端当前桌面，可观看或操作。**Android 手机镜像**以解锁并授权后的观看和操作为基础。熄屏继续操作可评估 Shizuku，锁屏状态下的可用性待验证。
- **副屏**把另一台设备用作扩展显示器。结束时收回扩展显示区。
- **Win↔Win 远端窗口**以单个窗口为单位。抓住标题栏跨屏拖动，应用和未保存状态留在原机，拖回后接着用。也可从对端启动应用并直接打开同样的可操作窗口。
- **输入与外设**覆盖键鼠、触控、屏幕键盘、笔、手柄和远端声音。麦克风与摄像头可按场景借用。USB 透传让用户把指定外设交给远端软件使用，用完归还。

短时断线可恢复时，接回同一笔文件传输或同一串流会话。关闭观看界面后，原机应用继续运行。隔空播放暂缓。

## Windows／Android 演示接入缺口

2026-11-25，依据原生客户端源码和 NSH 入网实验 `8176a19c` 记录。当前继续做入网与授权演示，完整剪贴板接力和文件传输留到对应场景。

- **设备显示名是 SDK 必需能力。** 添加设备时默认使用宿主系统提供的设备名，用户可以在提交申请前修改。SDK 将显示名与该设备的唯一 ID 关联并持久保存。申请端随申请提供当前名称，批准端可同时读取名称和 ID。申请提交后改名仍然生效，批准端在下次联系时能看到新名称，同一笔申请继续。入网后设备改名通过成员同步更新。显示名允许重复，离线也可以改名，无需全网协调。调用方可用短 ID 区分同名设备，SDK 提供完整 ID 用于身份识别和授权。目前申请和成员数据均缺少名称字段。[申请数据](../../src/manual_admission.rs#L97) · [成员数据](../../src/native_network.rs#L158) · [早期设备描述讨论](2026-09-28-network-scenario-walkthrough.md#1-首个场景老成员返回)
- **管理记录自动传播。** `NativeClient` 已能签名并保存设备管理操作，也能调用 `sync_services()` 主动交换一次。管理 Replica 已有专用协议。实验客户端仍由界面控制器每 8 秒向原邀请设备拨号，缺少节点侧变更后的传播和重连补齐。正式接入要覆盖在线任免、授权方离线后从持有记录的成员补齐，以及移除记录的交付和生效后的连接关闭。[设备操作](../../src/native_device_management.rs#L134) · [单次交换](../../src/native_services.rs#L582) · [Replica 维护](../../src/network_maintenance.rs#L816) · [成员移除约定](../../CONTEXT.md#L136)

  **主动退出的首次交付。** 原生和浏览器沿用同一约束。普通成员自行确认退出，管理员退出需要逐项创世确认。本机保存并应用签名退出记录后停止成员通信。SDK 主动交付这条记录。任一其他现有成员验证并持久保存后回执，即完成退出端的交付责任。普通成员也可以接收并转发。若首次交付尚未确认，退出端重开仍保持离网，并在成员可达时续交原记录。常规策略同步和 Replica 对成员资格的要求继续生效。[退出约定](../../CONTEXT.md#L126) · [浏览器退出实现](../../browser-probe/src/device_management.rs#L198) · [浏览器同步门控](../../browser-probe/src/network.rs#L674)

  **三节点验收。** A 退出时 C 离线，B 收到并保存 A 的记录后回执。随后关闭 A 并重开 B，再让 C 上线。B 能从本机恢复该记录，C 能从 B 同步、验证并保存，重开后两者的成员列表都反映 A 已退出。另覆盖首次交付前 A 关闭的情形：A 重开时可查询“本机已退出，交付尚未确认”，并能在 B 可达后完成交付。当前 Edge 实测仅覆盖本机退出和重开。[Edge 实测](#laptop-edge-实测)

  **离线期间被移除。** 被移除设备重开后联系持有移除记录的成员时，SDK 自动交付或取回针对该设备的签名移除决定及验证所需的记录。接收端验证、保存并确认移除对当前成员资格生效后，报告“已被移除”，停止按旧资格重连。只有联系超时时，报告“暂时无法联系”，保留上次已确认的成员状态。验收时让作出移除决定的管理员离线，由另一个持有记录的普通成员完成交付。[成员移除约定](../../CONTEXT.md#L136)
- **本机状态订阅。** `status()`、`requests()` 和 `device_operations()` 已提供快照。实验通过定时刷新显示角色、待审批申请和入网阶段。界面需要在启动或恢复时读取快照，并在本机验证、保存并应用变化后收到通知。管理员收到新申请、待审批列表变化时也需要 SDK 通知。后续剪贴板连接和文件任务同样已有快照，接入对应界面时可沿用同一种状态观察方式。[节点状态](../../src/native_client.rs#L494) · [入网请求](../../src/native_client.rs#L615) · [设备操作列表](../../src/native_device_management.rs#L108) · [剪贴板状态](../../src/native_clipboard.rs#L372) · [文件任务](../../src/native_client.rs#L560)
- **批准端读取入网交付结果。** 协议收到加入端的保存回执后，将该笔申请的交付状态持久化为 `Complete`，`NativeNetwork::approved_admission()` 能按申请查询。`NativeClient::approve()` 返回批准当时的状态，`requests()` 只列待审批申请。正式界面缺少从 `NativeClient` 读取或订阅该笔已批准申请后续进度的入口，无法据此把「等待对方保存」更新为对方已保存。[底层查询](../../src/manual_admission.rs#L242) · [回执保存](../../src/manual_admission.rs#L515) · [客户端审批](../../src/native_client.rs#L651)

### 建网时确认恢复卡已保存

原生和浏览器 SDK 已分别持久保存恢复卡的导出状态和用户的保存确认，公开状态还缺少导出进度。SDK 应允许调用方在重开后读出“尚未导出”“已导出，待用户确认”或“用户已确认保存”。已导出的用户可以直接确认已妥善保存，也可以再次导出。只有用户明确确认保存，建网设备才能进入正常使用。[恢复卡约定](../adr/0013-genesis-recovery-card-without-mandatory-password.md) · [原生状态](../../src/native_client.rs#L805) · [浏览器导出与确认](../../browser-probe/src/onboarding.rs#L247)

### 全网准入密钥轮换

用户以创世权限发起轮换后，SDK 负责向保留成员分发新准入密钥并收集其持久保存回执。离线成员重新上线后自动续传，发起端重开仍继续同一次轮换。调用方可查询哪些成员已确认、还在等谁。只有仍保留的成员全部确认保存后，才可按既有创世权限规则切换；设备暂时离线不会被自动移出保留成员。[既有轮换约定](../../CONTEXT.md#L37) · [底层分发与进度](2026-10-01-admission-rotation-validation.md#selected-integration)

### 迁入另一网络

旧网全部创世凭证副本永久丢失时，可创建新网，由各设备分别确认迁入。新网独立授予资格。SDK 负责在旧网仍可用时取得并保存新网入网资料，验证与新网成员的实际通信。用户已确认迁移且新网已验证可用后，设备可以停止使用旧网，只在新网运行。这也适用于已失去旧网创世凭证的旧网管理员。SDK 保存进度，正常重开后续办，调用方可查询当前使用的网络和迁移阶段。[领域约定](../../CONTEXT.md#L55) · [迁移决定](../adr/0006-prepare-network-migration-before-switch.md)

旧网正式退网沿用 ADR 0007：普通成员可以自行签退，仍具管理员资格的设备自退须由旧网创世凭证签名。若全部副本丢失，设备可以已在新网运行，旧网仍保留其原管理员资格。现有原生流程把旧网创世权限检查放在本机切换之前，SDK 需分别表达本机切换结果与旧网退网结果。[签名权限约定](../adr/0007-signed-management-authority-mapping.md) · [原生切换条件](../../src/network_migration.rs#L356)

### 本机状态观察与准入接收

2026-11-26 确认。调用方启动或恢复时可取得完整的当前状态，并连续观察之后的变化。通知可以合并，读取与开始观察之间发生的变化也必须可见。某笔申请的处理结果可按申请查询。

### 人工入网交付回执

2026-11-26 确认的 SDK 设计约束。原生和浏览器对同一笔人工申请提供一致的语义，沿用现有的申请设备身份和申请编号。[申请标识](../../src/manual_admission.rs#L94)

- **申请端**重开后能读到最后确认的进度：已创建且尚未确认送达、批准端已收到并待审批、已取得授权且待收齐资料、本机已验证并保存全部资料，或申请已被拒绝。一次联系超时可以单独报告，已确认的进度保留。申请端保存完整资料后即可按有效成员资格使用网络。[入网成功定义](../../CONTEXT.md#L110) · [批准端保存申请后应答](../../src/manual_admission.rs#L422)
- **批准端**能按原申请查询待审批、已拒绝、已批准且尚未收到保存回执，或已收到保存回执。结果在重开后可读。只有收到并保存回执，批准端才能确认申请端已保存完整资料。[回执持久化](../../src/manual_admission.rs#L515)
- **回执中断**时，由申请端 SDK 在双方运行且原批准端可达后自动补交。沿用原申请和原批准。批准端已经保存回执、最后的确认在途中丢失时，重复补交得到同一结果。补交期间保留申请端已完成的本地入网状态。[浏览器保存与发送回执](../../browser-probe/src/network.rs#L2841) · [现有续办入口](../../browser-probe/src/onboarding.rs#L293)
- **批准端的近期申请记录**可在重开后直接查询，调用方无需另存申请编号。同一设备重新入网时按新旧两笔申请分别查询。旧授权失效后停止按该授权续办，保留期内仍可读到该笔申请实际收到的最后结果。当前成员资格由成员状态给出。
- **资源有界。** 近期申请历史和诊断日志的存储占用都有上限。同一申请反复重试只更新原记录。在有效授权下，中断的交付仍可续办。

### laptop Edge 实测

2026-11-25，使用 Windows `laptop` 上的 Edge `156.0.4314.50` 独立测试配置。受控用例由本机独立 Chromium／WASM 管理端批准，回环 Relay 经 SSH 转发给 Windows，只用于本次隔离网络。

1. Edge 的 NSH 页面粘贴邀请并显示「等待管理员批准」。管理端收到该设备的申请。关闭 Edge 的申请标签页后批准，管理端当时显示交付未确认。重开标签页后，Edge 用原测试身份 `69fd3557bb27` 完成入网并显示普通成员，管理端记录 `delivery_confirmed: true`。
2. Edge 与 Chromium 在真实成员连接上交换 `PING`，选中路径为 Relay。主动尝试改善路径返回 `DeadlineExceeded`，直连未建立。失败后再次发出请求，仍从 Relay 收到回复。
3. Edge 点击「退出网络」并确认，随后显示「本机已离开网络」。重载后原设备 ID 和离开状态都保留，页面关闭了成员操作。管理端重开后的本地成员列表仍保留该设备，这次只验证了本机离开，未观察到退出记录自动传播。

与 Pixel 管理端的公网混合联测停在准入联系。Edge 成功打开公网 Relay WebSocket，SDK 请求随后超时，Pixel 未显示该测试身份的申请。单独指定 Pixel 邀请中公布的 Relay 后，准入仍超时。该场景尚未进入成员路径测试。
