# 原生 iroh 融合的行为基线

首个原生融合成员往返的行为对照和构建结果见 [MIOPUNCH-143 双端实测](../evidence/native-iroh-member-fusion-143.md)。

基线为 `694f004d`，含当时的工作树、双端诊断、测试和 vendor 修改。下表区分已有保证与融合有意改变的行为。优先用真实两端和可控的 netns、relay、消息入口对照。业务回复须核对对端和内容。迁移旧 SDK 测试时保留原触发、期限及核心断言，ping 或专用流都可作为载荷。

**现场样本的用途。** 旧版 `9d3db16c` 已做过办公室→热点→办公室。MIOPUNCH-141 是对当前交付版的人工切网观察，记录两端实际版本、网络位置、首份有效回复和原流连续性。已记录的 `8ab55370` 证明 Windows 本地提交了三份回包，Linux 没有记录匹配包；家宽 WAN 是否收到仍待观察。140 表中的 2.248 秒和其中的 1.862 秒来自同一次后台控制拨号，首笔业务回复另行计时。[现场记录](../evidence/network-demo-140-2026-11-18.md#后台中继竞速与双端-udp-分段计时)
