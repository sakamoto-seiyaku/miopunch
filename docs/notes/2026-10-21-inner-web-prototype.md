## 实际结果

独立浏览器节点通过真实入网流程取得成员资格，建立到原生节点的成员连接。浏览器中的请求经该连接交给原生节点访问测试站点，再在客户端的独立来源内容区呈现。测试网址仅由原生提供端解析，浏览器没有直接请求目标站点。

已跑通 HTML、样式、脚本、图片、Fetch API、页面跳转、表单 POST、303 跳转，以及由提供端 cookie jar 维持的测试登录。内容页无法读取管理页或节点句柄；未入网访问、越界目标、目标不可达与关闭后的连接均有实际拒绝／失败证据。两个运行进程正常退出，临时节点材料已清除。详见[运行回执和截图](../evidence/inner-web-prototype-2026-10-21/README.md)。

## 结论及边界

现有成员连接足以承载这一小型 HTTP 往返；不同来源的内容页面可以通过受限桥接使用它，同时与持有节点对象的管理页面分开。这补充了“页面数据能经节点往返并交互”的运行证据，不是完整网页模块或最终容器选型。

原型仅开放一个测试目标，使用每请求启动 curl 的临时适配、小体积报文和单一用户的提供端 cookie jar。通用目标配置、生产服务 ACL、多用户会话、完整站点兼容、WebSocket、HTTPS 目标、流式数据和各平台宿主仍未验收。此轮没有将这些临时机制写成产品决定，也没有改动既定 Vue/Tauri/Rust 分工。

## 运行

在仓库根目录执行：

```sh
rtk proxy python3 browser-probe/prototype-web/run.py
```

打开命令输出的本地地址，点击“连接节点”，再点击“打开网页”。`--check` 执行同一页面的自动操作并保存截图与回执；现有匹配构件按哈希复用。原型需要本地浏览器、构建工具，以及已经保留并验证的 Browser SDK 产物；[说明](../../browser-probe/prototype-web/README.md)列明范围与入口。

本轮新增的运行代码均为可丢弃原型。没有提交或合并到主分支的产品实现，也没有启动其余四个业务模块。
