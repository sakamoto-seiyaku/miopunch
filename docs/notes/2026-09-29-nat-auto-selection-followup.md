## September29 原始讨论记录


日期：2026-09-29。性质：用户已明确的方向及源码缺口记录；不重新决定是否使用探测驱动策略。实施范围以 Plane 子票为准。本页与 [NAT3/4 范围](2026-09-29-nat34-strategy-scope.md)配套，不改其已有验收。

用户明确：沿用旧版「通过 S 探测行为选择算法」的方向，适配当前 Rust/iroh 流程；不能让实验拓扑标签、手填 NAT 类型或环境变量代替节点运行时的自动判定。旧代码中的 S 探测具体是从多个 STUN 目的地采样外部映射：`nat/discovery.go:33-52` 逐个取得地址，`nat/classify.go:42-103` 根据公网 IP/端口变化形成 Easy/Hard、端口跨度及“规律”粗特征。此过程没有测得过滤行为，故 NAT3 的 APDF 仍需独立内核实验台证明，不能增设「先自动识别完整 NAT3/4」这个错误前置。

旧 `internal/punchdecision/decision.go:684-735` 在双方至少两个映射地址可用时分类、选角色和目标区间，缺样本时按基础策略回退；`nathole_analysis.go:183-219,275-304` 把双方特征映射到 mode 0–4：双 Easy 用 mode0；单 Hard 且规律先 mode1，否则先 mode2；双 Hard 且均规律先 mode3，一侧规律先 mode4，其余作有限试探。`internal/punching/punching.go:347-395,413-502,700-850` 将结果执行为收发角色、时间窗口、范围或随机目标尝试。旧 `daemon_memory.go:44-81` 有按对端作用域保存成功策略反馈，但旧常量、额外监听 socket 和得分规则不是可直接复制的产品预算。

当前 [MIOPUNCH-56 代码](../../src/bin/udp_nat_probe.rs)可在真实 NAT3 中执行协调探测，但 `MIOPUNCH_NAT_STRATEGY` 在 `:393` 和 `:597` 人工选择基础/协调分支，仅适合作对照试验。MIOPUNCH-57 正在将同一 QUIC UDP socket 的多目的映射观测、稳定/规律/未知特征和单侧规律 NAT4×稳定对端的 mode1 等价策略串成自动链路；57 不覆盖双 Hard、随机 Hard 或所有分支的统一默认路由。后续 [MIOPUNCH-58](http://192.168.4.22:2080/work/projects/aa58cd82-2afc-404b-a097-58ef553c7ca4/issues/841d7c0d-6438-43a2-b476-3927875b604d) 应使双规律 Hard 自动进入 mode3 等价方案；[MIOPUNCH-59](http://192.168.4.22:2080/work/projects/aa58cd82-2afc-404b-a097-58ef553c7ca4/issues/ef55c03d-841d-4849-96e2-9556ac00da40) 应使单侧不规则 Hard、规律×不规则 Hard 自动进入 mode2/mode4 等价的安全有界方案，并如实处理双不规则与未知。最后的 [MIOPUNCH-60](http://192.168.4.22:2080/work/projects/aa58cd82-2afc-404b-a097-58ef553c7ca4/issues/506be324-bc43-444d-a4e1-44624e53e3dc) 整合验收：真实 S 观测→双方特征交换→按特征及可用策略自动选择 mode0/1/2/3/4 等价路径→同一认证连接上的探测、QUIC 路径和业务。实验开关可保留用于 A/B 测量，但正常运行不能依赖它作策略选择。

自动选择必须在身份和秘密/成员准入闸门后使用受保护的短寿命观测，并绑定本轮、双方节点、实际 socket 和维护预算。旧样本不足时不能无限猜端口；网络变化或旧候选应失效，失败可走获准备用路径。若采用旧式成功反馈重排，只能在经过验证的同一身份/网络/映射条件下记成功，不能跨撤销、换网或新秘密代际沿用。低 TTL、随机多 socket 监听与旧包数是具体执行机制，需按当前 QUIC socket 和用途隔离验证等价性，不能因方向已确定就假定旧实现可直接移植。
