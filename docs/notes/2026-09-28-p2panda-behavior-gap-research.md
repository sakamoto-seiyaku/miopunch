# p2panda 0.7.1 行为缺口与复用边界调查

日期：2026-09-28。性质：设计研究，不是选型定稿或运行验证。依据 [产品主线](2026-09-27-product-mainline-draft.md)、[S0-S5 场景](2026-09-28-network-scenario-walkthrough.md) 和 [最新讨论第 19-21 节](2026-09-27-network-repositioning-discussion-draft.md#19-2026-09-28暂停-acl按实际场景推进)。本轮暂停服务 ACL，不设计“应用开放策略 + 管理员 ACL”双配置；普通记录冲突可采用成熟自动规则。创世权恢复与有限次 precode 指定唯一核销节点只作为 auth 适配约束，不在此重开入网设计。

## 证据边界和总判断

本次按官方 GitHub `v0.7.1` 标签源码走查，所有源码链接均指向该标签；未编译、运行或进行网络实验。标签中各 crate manifest 标 `0.7.1`；[`p2panda-net/Cargo.toml`](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/Cargo.toml#L1-L17) 的 `iroh = "1.0.3"` 是 Cargo 兼容范围 `>=1.0.3,<2.0.0`，不等于固定只能用 1.0.3；同一 manifest 的 `iroh-base` 也须统一解析。能否直接与 iroh 1.2 或保持兼容版本号的 fork 编译，仍需验证 API 和 feature 组合，不能只凭 semver 宣告成功。[依赖与 feature](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/Cargo.toml#L24-L88)。标签自带 CHANGELOG 顶部仍有 `Unreleased` 段，不能把当前 `main` 或此段后来描述的 high-level helper 不经核验地当作发布版接口；以下以标签实际代码为准。[CHANGELOG](https://github.com/p2panda/p2panda/blob/v0.7.1/CHANGELOG.md#L10-L32)。

**推荐边界（判断）：优先保留 `core`、`store`、`stream`、`sync` 及 `net` 中的 AddressBook、Discovery、Gossip、LogSync 编排，并对 `net` 的 iroh Endpoint 构造、按 ID 寻址入口和成员准入做小范围适配。** 不优先采用未接入 group auth 的 high-level `p2panda::Node` 作为产品控制面，也不因连接 fork 冲突就把整套 `net` 抛掉重写。iroh 深 fork 内部仍统一负责联络渠道、打洞、连接与路径维护；p2panda 负责已建立端点连接上的发现、数据传播和持久补齐。这个边界是源码支持的工程推论，不是已验证的集成结果。

## 模块覆盖到哪一步

| 模块 | 发布版现成能力与省下的工作 | 不能替宿主完成的部分及证据 |
| --- | --- | --- |
| `core` | Ed25519 作者签名、操作头/正文哈希和大小验证、逐作者链与可裁剪前缀；不用自造记录认证格式。[验证实现](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-core/src/operation/validation.rs#L9-L76) | `body=None` 时只验证头，不能证明正文已保存；作者签名不证明作者在某产品私网有权限。 |
| `store` | SQLite 保存操作头与 `body` BLOB，存日志、topic、cursor、地址簿及 group state，并有事务接口；免写基础持久索引。[操作写入](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-store/src/operations/sqlite.rs#L31-L87) | 是否保留某类有效正文、何时剪裁及空间预算由产品定；允许清空 payload，不能把只存签名头称作 S2 正文副本。[payload 删除](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-store/src/operations/sqlite.rs#L171-L190) |
| `stream` | `Ingest` 校验 operation 与 backlink、去重，并在事务中 `insert_operation` + `TopicStore::associate`；可复用验证到持久化的主要流水线。[Ingest](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-stream/src/ingest/operation.rs#L16-L89) | 业务记录格式、授权语义与本地视图仍由宿主处理；失败处理不可把无效记录当作有效网络状态。 |
| `sync` | 双边 topic handshake、按 topic 聚合多作者日志、按各日志进度差异互补、body 传输及 live mode；免写 EBT 式日志补齐主体。[topic 日志](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-sync/src/protocols/topic_log_sync.rs#L32-L48) [范围发送](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-sync/src/protocols/log_sync.rs#L360-L404) | 协议收到操作只发 `OperationReceived`，自身不保证摄取/落盘；单用 lower `sync` 要接 `Ingest`。[接收事件](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-sync/src/protocols/log_sync.rs#L308-L345) |
| `net` Endpoint/AddressBook | Endpoint wrapper、同一 iroh Endpoint 的 ALPN handler 注册、持久地址簿/引导点/失效报告；可省一层协议路由和联系信息索引。[Endpoint API](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/iroh_endpoint/api.rs#L105-L169) | `Builder` 自建 Endpoint，不公开注入已有实例；`IrohConfig` 只有绑定地址和端口，fork 新增的联络/路径旋钮要在一处构造边界下传。[Builder](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/iroh_endpoint/builder.rs#L14-L20) [Config](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/iroh_endpoint/config.rs#L5-L24) |
| `net` Discovery/Gossip/LogSync | 随机游走、topic 集合匹配、候选地址传播、在线 gossip、失败重试与 topic sync 会话管理，省去部分互联副本传播的调度。[发现 walker](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/discovery/actors/walker.rs#L125-L174) [LogSync builder](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/sync/log_sync/builder.rs#L25-L70) | 没有 MQTT/IRC 定向私密信令、任意业务数据中继或完整产品连接策略；gossip 是在线传播，持久补齐来自 sync。 |
| `auth` | group 成员/权限操作、因果依赖和 strong-remove 等自动冲突解析，可作为管理状态验证组件。[auth 范围](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-auth/src/lib.rs#L5-L61) | 发布版 high-level `p2panda` 依赖没有 `p2panda-auth`，其 `Network::spawn` 只接 net 诸模块；不存在现成的“未知成员凭证交换→准入→正常 sync”流水线。[high-level 依赖](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda/Cargo.toml#L30-L40) [组网组合](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda/src/network.rs#L35-L94) |

`p2panda-net` 将 iroh 与 net 功能绑定：`discovery` 依赖 `iroh_endpoint`，`gossip` 同时依赖 `iroh-gossip` 和 Endpoint，`sync` 又依赖 `gossip`/Endpoint；因此“只改一项 Cargo feature 就让 net 使用已有外部 Endpoint”不成立。[feature 图](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/Cargo.toml#L24-L64)。反过来，这些模块已复用了统一 wrapper 与同一 ALPN accept loop，不支持“net 必须全部重写”的结论。

## S0-S5 行为映射

| 场景 | 可直接复用并省下的工作 | 宿主仍需实现或薄适配 | 事实 / 推论 / 未知 |
| --- | --- | --- | --- |
| **S0 长期离线返回** | SQLite 地址簿保存已知节点、bootstrap、transport info，Discovery walker 从 bootstrap 或其他已知节点持续随机游走并按成功率退避；LogSync 可随后补齐。[随机游走](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-discovery/src/random_walk.rs#L92-L159) [退避](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/discovery/actors/walker.rs#L125-L174) | 产品提供初始入口；iroh fork 维护可用路线、旁路寻址与可联络状态。p2panda 的 walker 只调自己的 discovery 会话，不是 S0 多渠道连接恢复总调度。打开客户端即恢复的启动时序由产品拼接，不等业务触发。 | **事实**：walker 独立常驻、可重试；**推论**：保留它可省候选发现工作；**未知**：与 fork 重试预算如何协调。 |
| **S1 双 NAT、MQTT/IRC 仅信令** | Endpoint 提供 iroh 安全连接与 ALPN 协议路由，net 可在连接形成后做发现、gossip、sync。[Endpoint actor 构造](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/iroh_endpoint/actors/endpoint.rs#L157-L204) | MQTT/IRC 的定向信令保护、候选交换、打洞调度与路径选择在 iroh fork；消息服务不是 p2panda 的数据连接。`net` builder 当前只传 relay/map、地址簿、绑定配置，需下传 fork 新接口。 | **事实**：发布 net 不含此旁路信令适配；**推论**：Endpoint 构造处薄改比上层重建连接编排合适；**未知**：1.2/fork API 编译结果。 |
| **S2 部分互联 A-B-C / C 离线** | `TopicStore::resolve` 取同 topic 的多个作者日志；B 只要持有 C 的原签名 operation，可从本地按 C 的作者键与日志进度给 A 发头和正文。高层 Node 的 stream 会把收到的 operation 交给 Ingest，后者验证、持久化、关联 topic，再向应用交付。[topic resolve](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-sync/src/protocols/topic_log_sync.rs#L128-L158) [高层处理](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda/src/streams/stream.rs#L200-L229) | 若选模块化 net 而不用高层 Node，必须给 LogSync 的事件接同等 Ingest 流水线；宿主决定哪些记录可复制、验证其业务含义、保留正文与有效验证依据，并幂等物化视图。不能把最小通讯录当复制上限，也不要求无限历史。后台主动争取互联由 fork 与 net 预算协调，不要求 fullmesh/每对 keepalive。 | **事实**：发布同步按作者日志转发而非只转本人；**事实**：协议事件不自动持久；**推论**：完成事件→Ingest 接线后可满足 C 离线补齐；**未知**：目标负载下的存储/剪裁预算。 |
| **S3 同一连接换路，失败后新连接** | `net` 将 iroh `Connection` 交给协议 handler；p2panda 不接管底层路径，保留 iroh fork 在同一连接切路的空间。[连接 actor](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/iroh_endpoint/actors/connection.rs#L97-L143) | 同连接换路、备用路径质量选择及彻底失败报告属于 fork。sync 会话失败可再开新连接补齐记录，但不能称旧业务 stream 自动 resume。 | **事实**：net 不实现任意业务恢复；**推论**：数据同步可在新会话继续；**未知**：新增载体能否保持同一 iroh Connection。 |
| **S4 A 不认识 C，旧 B 离线** | 已有 bootstrap 的地址簿条目可启动 random walk；与可达候选建立 discovery ALPN 连接后，PSI topic 交换可得到本地未知 C 的线索。此能力不要求 C 预先出现在 A 的通讯录。[bootstrap 选择](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-discovery/src/random_walk.rs#L117-L159) [PSI 会话](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/discovery/actors/session.rs#L96-L143) | 候选可达、持有匹配 topic 不等于合法成员。发现路径要求至少一个可达且理解相应 discovery 协议的入口；仅有不能承载此协议的 MQTT broker/relay 不能直接充当 walker seed。产品需提供取得 C 身份与必要授权依据的受限引导路径，然后准入正常 sync；不要求 B 或先完成全量状态同步。 | **事实**：discovery 可扩展到未知 ID，但发布版没有成员 proof/Authoriser 接线；**未知**：共享 bootstrap 的 network/topic 映射、最小可验证凭证形式及撤销新鲜度。 |
| **S5 禁用官方 relay / 自建替代 / 质量优先** | Endpoint builder 接收自定义 relay URL；net 自身不强制写入某官方 relay，未配置时使用 `RelayMode::Custom` 的空 map。[relay 设置](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/iroh_endpoint/builder.rs#L49-L73) [actor](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/iroh_endpoint/actors/endpoint.rs#L174-L195) | fork 必须统一筛选获准资源，并禁止后续隐式 fallback；连接质量选择、普通节点显式启用的数据中继在 fork/产品配置。地址查询与 relay 使用分别审计，不能只看 Builder URL。 | **事实**：net builder 可无 relay 或自建 relay；**未知**：fork 新地址查询、观察与中继路径是否都遵循禁用策略。 |

### S2 的确认、重放、幂等与正文

`LogSync` 的 receive 分支解码头/可选正文并广播 `OperationReceived`，不是数据库 commit。[源码](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-sync/src/protocols/log_sync.rs#L308-L345)。`Ingest` 先调用 `validate_operation`，再在事务中检查 hash 是否已有、验证前一条日志链接、写 operation 并关联 topic；重复输入返回 `AlreadyExists`。[源码](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-stream/src/ingest/operation.rs#L38-L89)。因此 C 的原作者身份在 B 转交时不被 B 替代，A 仍须按记录所属领域判断 C 有无权发布；签名和日志完整性只解决载体有效性。

SQLite 操作表真正有 `body` BLOB，写入时绑定 `operation.body`；`validate_operation` 在 `body=None` 时不会比较正文哈希，因此 S2 成功标准应检查 C 的有效正文与验证依据经 B 重启仍可从 B 补齐，而非只数 header。[存储](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-store/src/operations/sqlite.rs#L34-L80) [校验](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-core/src/operation/validation.rs#L17-L47)。高层 stream 的 `ack()` 更新本地已消费 cursor，未确认事件可从本地 replay；这不是远端已收到或业务动作恰好执行一次的证明。[cursor](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda/src/streams/acked.rs#L80-L138) [replay](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda/src/streams/replay.rs#L20-L47)。物化状态及有外部副作用的处理仍按 operation hash 幂等，ack 在业务持久提交后推进；若直接复用 high-level stream，尤其要明确其 `Automatic`/`Explicit` ack 选择。[高层处理](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda/src/streams/stream.rs#L369-L402)。

### S4 的发现与准入顺序

发现层有实际复用价值，但不证明完整入网恢复已经具备。random walk 从地址簿的 bootstrap/已知节点选择下一跳，发现会话通过 `endpoint.connect_with_config(remote, DISCOVERY_PROTOCOL_ID)` 建 QUIC，再做 PSI topic 交换。[walker](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-discovery/src/random_walk.rs#L117-L159) [session](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/discovery/actors/session.rs#L96-L143)。**发布版的地址传播边界比模块简介宽：** `PsiHashDiscoveryProtocol::new()` 用默认配置，而 `share_nodes_with_common_topics` 默认 `false`，会向对端发送本地所有节点的 transport info；PSI 保护 topic 比较，不自动限制所有地址线索只给共同 topic。[配置与发送分支](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-discovery/src/psi_hash.rs#L48-L145)。低层有 `with_config` 可设该 flag，但 `net::DiscoveryConfig` 只配置 walker 数量和 reset 概率，session 固定调用 `new()`；若产品决定缩小传播范围，需要薄适配下传，不能宣称高层已有开关。这不预设产品必须采用最小通讯录。[net 配置](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/discovery/config.rs#L1-L45) [session 构造](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/discovery/actors/session.rs#L120-L127)。`NetworkId` 是协议 ALPN 的 BLAKE3 混合输入，源码特别警告 **不是秘密**；它既非产品私网成员证明，也不预设等同产品私网 ID。Endpoint API 旧注释将它叫 shared secret，与实际实现和显式警告不一致，应以后者为准。[定义与警告](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/lib.rs#L285-L325)。共用 bootstrap 能否服务多个私网，取决于 NetworkId/topic/受限引导协议的映射与可达性，当前未知，不能推成必需每网专服。

`p2panda-auth` 的 `GroupCrdt::process` 依据操作的 dependencies 还原作者当时权限并验证；`Groups` processor 可保存 group state，但这不构成一个可从陌生 C 独立取得、验证且绑定当前 iroh EndpointId 的现成凭证协议。[auth process](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-auth/src/group/crdt/mod.rs#L510-L560) [groups processor](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-stream/src/groups/processor.rs#L58-L115)。发布版 sync 入站只通过 topic handshake 找订阅 topic 后路由，没有根据 group state 完成员准入；不能把“知道 topic”提升为授权。[sync handler](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/sync/actors/manager.rs#L512-L550) [topic 路由](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/sync/actors/manager.rs#L404-L426)。若未来把正常 sync 严格限制为已在本地 group state 的 C，而 C 的授权材料又只能通过该 sync 获取，就会形成先同步再认证的循环。这是需要避免的**集成风险推论**，不是 p2panda 自身硬要求。

同一 Endpoint 可用 `Endpoint::accept<P: ProtocolHandler>` 注册附加 ALPN，并由已有 accept loop 路由；这为受限证明交换留下扩展点，不要求另起第二个 iroh Endpoint，也不代表库已实现该证明协议。[注册 API](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/iroh_endpoint/api.rs#L129-L145) [actor 路由](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/iroh_endpoint/actors/endpoint.rs#L196-L215)。具体握手与证明材料仍需选成熟机制；创世凭证可恢复管理、有限次 precode 只能由唯一指定节点核销，不得由 topic、relay 或所有在线节点共同默认裁决。

## 与 iroh fork 的最小接口改动

1. **Endpoint 构造：** 当前 actor 固定用 `iroh::Endpoint::builder(presets::Minimal)`、自有 AddressBookDiscovery、`RelayMode::Custom`、固定 QUIC keepalive/idle 并启动一个 accept loop；`IrohConfig` 仅绑定地址/端口。fork 的多渠道联络、地址查询、路径选择/自定义 transport 及禁用策略需要在这一个构造边界下传或复用同一实例；优先评估薄参数/工厂适配，而不是在产品上层再写一套连接循环。[构造实现](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/iroh_endpoint/actors/endpoint.rs#L157-L204)。
2. **拨号入口：** `ToIrohEndpoint::Connect` 先查 `AddressBook::node_info` 并转为 `EndpointAddr`，缺失便返回 `TransportInfoMissing`，不会触发 fork 新增的按 ID 寻址或旁路信令。需明确地址簿和 fork 的寻址/拨号所有权，允许新候选线索进入同一个 fork 连接过程；这是一处实质适配，不是“两次建连”已发生的证据。[早退](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/iroh_endpoint/actors/endpoint.rs#L238-L272)。
3. **准入与身份：** `p2panda-net::NodeId` 是 `p2panda-core::VerifyingKey`，其 `utils` 通过同一 Ed25519 字节转换为 iroh key，因此可选择同一节点密钥避免双节点 ID；但“公钥相同”仍不证明产品成员资格，根权/创世凭证也不必等同日常 Endpoint key。[类型](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/lib.rs#L279-L283) [转换](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/utils.rs#L116-L131)。准入需要覆盖 Discovery、Gossip、LogSync 和业务协议的适当边界，同时允许 S4 的受限引导；发布版没有一处可直接接 group auth 的统一 authorizer。准入发生在 QUIC/TLS 前、中、后的精确时序仍待实验，不以“先全量同步”定死。
4. **状态/连接分工：** AddressBook 维护可供尝试的线索与失效报告；Discovery 的退避与 LogSync 的重连面向各自协议，不替代 fork 对多渠道联系和同一 Connection 路径切换的全局调度。[连接结果回报](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/iroh_endpoint/actors/connection.rs#L125-L165) [发现退避](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/discovery/actors/walker.rs#L125-L174)。

**候选取舍：** 整套 high-level `Node` 最省样板但锁定 `Network::spawn` 的固定模块组合、当前未接 auth，也很难控制 fork 的构造/准入时序；`core/store/sync` 最灵活但需自己重做地址簿、候选发现、gossip 修复、topic session/ALPN 调度。模块化 `net` 加上述薄适配通常最少自写且保留成熟机制；若小实验发现 builder/拨号/准入修改导致大面积分叉，再退到 `core/store/stream/sync`，而非先验排除 `net`。[high-level 组合](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda/src/network.rs#L35-L94) [net 模块](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/src/lib.rs#L235-L277)。不叠加第二套 SSB EBT 实现；EBT 只是比较缺失补齐行为的参考。

平台边界：`net` 的默认 feature 包括 iroh、mDNS、SQLite 地址簿、gossip 与 sync，不能从这些 manifest 推出当前浏览器端完整可运行，也不能据此断言不可移植；移动端完整运行同样未在本轮验证。[feature 图](https://github.com/p2panda/p2panda/blob/v0.7.1/p2panda-net/Cargo.toml#L24-L64)。

## 建议的小验证实验（尚未执行）

1. 用固定 `0.7.1` crates 与 iroh 1.2/同版本 fork 做只编译的 API/feature 矩阵，验证 `Endpoint` 构造、`iroh-gossip`、`iroh-base` 是否能统一解析；记录实际需要改的 `net` 行数。
2. 三节点最小 S2：C 发布带正文的普通记录，B 摄取并重启，C 下线，A 从 B 补齐；检查作者仍为 C、body 落盘、重复转交幂等、失败后应用 cursor replay，分别试模块化 `LogSync+Ingest` 与 high-level stream。
3. S4 引导分层：A 只有已离线 B 和一个获准 bootstrap，C 为唯一在线新成员；验证 discovery 能否取得 C 线索，随后仅交换必要可验证成员材料并绑定 C EndpointId，再开放正常 LogSync。额外测 bootstrap 不持有产品私网权限、仍可转交线索的边界。
4. 在同一 wrapper Endpoint 注册窄 ALPN handler 与 Discovery/LogSync，验证共用 accept loop、网络 ID/topic 映射、受限引导和成员准入不会互相阻断；不在实验中自造密码握手。
5. 禁用官方 relay、配置自建资源后走“无地址簿 EndpointAddr 但 fork 可按 ID 联系”的路径，检查早退适配、无隐式官方 fallback，及路径变化与断连时向上层报告的边界。
