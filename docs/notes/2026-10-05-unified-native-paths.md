# Native paths behind the common member coordinator

MIOPUNCH-79 implements the native adapter seam accepted in [ADR 0009](../adr/0009-unified-session-and-capability-based-paths.md). The existing UDP and TCP traversal algorithms now prepare an owned candidate. The common coordinator performs capability negotiation, fresh authenticated ACK on the original member connection, bilateral readiness and final authorization checks before retention. Callers continue to use SDK `connect`/`accept` and streams without choosing a transport.

`NatConnector` exposes its existing preparation and commitment separately. `TcpPunch` similarly retains its claim, observation and circuit in `PreparedTcpPath` until commitment. Native candidates carry the original weak connection, current qualification, network generation, route, optional local socket and exact path ID. Failed uncommitted candidates retire their own path; retained physical owners move to the original connection. No iroh/noq fork, traversal interval, algorithm, scoring rule or allowance was changed.

The controlled evidence is [the receipt](../evidence/unified-native-paths-2026-10-05/receipt.json). Five representative SDK stories used independent persisted member identities and real Linux kernel NAT gateways. Preparation uses actual approval and admission material delivery; actors close and reopen their stores before connecting. Successful stories exchange a bidirectional business request/reply, ingest a nonempty verified management record stream and reopen the durable records afterward. This is a member business/management-record story, not a qualification of the separate replica ALPN.

All stories use one 45-second caller context. Internal traversal bounds and node allowances are inherited; cleanup is measured separately. Every applicable UDP socket and TCP listener rebind succeeded immediately after SDK shutdown and again after at least 100 ms. TCP queues were empty. Owned containers and namespaces were independently observed absent. The TCP-only endpoint has no bound UDP socket; its empty UDP rebind array is not a UDP release assertion.

The asymmetric story exposed a real integration bug: an endpoint without TCP observers left the private TCP phase early while its peer read UDP control bytes as a TCP candidate. The preserved red fixture exits 1 and returns InvalidControl on the responder. The fix keeps both peers in the existing TCP unavailable-status exchange. An unsupported TCP enhancement does not query observers or prime a circuit. The existing Linux-only punching guard remains; Android TCP punching is not enabled or qualified.

The supported Linux paths in the four established stories keep the same active observation, preparation, commitment and budget behavior; those unaffected stories are reused, not presented as runs of the later binary.

The broad source snapshot changed during the blocked run only because the separate `browser_wss_member_native` bin was edited. Its original `sourceUnchanged=false` remains in the raw receipt. Cargo built only `unified_native_member` plus the package library; the actual input subset remained unchanged. The receipt lists that subset and the excluded unbuilt target instead of rewriting the original result.

Earlier actor observations used advertised IP hints and libpcap buffering omitted short capture tails. The final observations use actual endpoint binds, durable reopen and immediate capture mode. Original first captures, exits and compiler failures remain archived. Final captures contain all filtered records with zero kernel drops. Public archives preserve exact link/IP/transport headers, timestamps and original wire lengths, with transport payload and STUN attributes removed. Capture counts include both WAN router interfaces and are not unique datagram or throughput measurements. Temporary public peer identifiers printed by the old TCP diagnostic are omitted with explicit transformation hashes; private stores and binaries are not published.

These results qualify the controlled native integration. They do not establish public NAT success, physical Android TCP support, broader NAT-mode coverage or a performance benefit. The separate public MQTT member story has its own source, device, route and cleanup evidence; it must report whether the SDK actually selected native data or a permitted relay. The public actor explicitly configures only approved Cloudflare and historical CN observation inputs, permits MQTT for signaling only and supports a physical Wi-Fi bind. It does not scan services or change default resource tables.

The first physical public native SDK story subsequently passed on Pixel6a and Y700. The host performed builds, ADB control and evidence capture only. Actual approval/admission preparation ran on Pixel with two independent identities and stores; only the fixture-owned client material moved through ADB to Y700. Both devices reopened their materials, then used normal MQTT TLS and the common member protocol. They selected path 1 on the permitted APS1 Iroh relay, received fresh authenticated ACKs on the original member connection, matched their peer identities, exchanged bidirectional business streams and reopened three durable verified records. Initiator and responder caller times were 14,245 ms and 18,630 ms under the unchanged 45-second fixture context; SDK cleanup took 160 ms and 3,901 ms separately. Both actual processes exited 0, primary UDP sockets rebound immediately and after 100 ms, and all owned processes, reader threads and directories were observed absent without forced termination. The original receipt is archived under `raw/public/android-first/receipt.json.gz` in [the evidence receipt](../evidence/unified-native-paths-2026-10-05/receipt.json).

The compiled Android artifact `444e9e146e80365ba59673fe1cda84c01d4cc3606918edc7fb285c64d858d358` was stripped on an owned deployment copy only, producing `e2e51cfdd49a8d4ea10048bf7b9cc7d7b71b044515b40c95f1b60d1e9cbe1ffb`. All 474 frozen build inputs matched current source, and source and artifact hashes stayed unchanged during the run. The fixture read actual own-process PID, UID, socket tuples and `SO_MARK` through temporary duplicated descriptors that it closed. Both primary Wi-Fi UDP sockets reported mark 0; connected TCP sockets reported nonzero marks. The selected relay path was not mapped to a unique TCP socket, so the UDP-specific UID/route collector correctly remained inapplicable. This success qualifies the real-device common SDK relay story, not direct native UDP/TCP traversal or physical egress. Zero native STUN send/reply diagnostic lines were logged; that is a log count, not an independent observer qualification or a packet capture.

Both actors also emitted the original `android context was not initialized` diagnostic. The plain ADB executable does not install a Java Application context. Inspection of locked `n0-dns-resolver` 0.1.0 shows that its Android system-DNS reader catches this missing-context unwind and returns an I/O error, permitting its configured DNS fallback. The diagnostic and stderr hashes are preserved; this story does not qualify Java system-DNS integration or claim execution without background diagnostics. No dependency, panic hook, route, permission or TLS verification was changed to suppress it, and no extra public or STUN test was run.
