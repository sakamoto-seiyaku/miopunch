# iroh 1.2.0 对 miopunch 场景的行为覆盖与 fork 缺口

日期：2026-09-28。性质：源码研究与候选验证计划，不是规格、实现或性能测试。固定基线为本地 `/tmp/miopunch-iroh-v1.2.0`，commit `17c0612f80f78f5288e97b818b1360ae6ea0a51a`；下文源码链接均锁定该 commit。官方 [iroh 1.2.0 Connection API](https://docs.rs/iroh/1.2.0/iroh/endpoint/struct.Connection.html) 也核对了公开的 stream、path 和关闭语义。不得把后来上游 `main` 的代码归入本基线。本轮没有构建 fork、运行网络实验或测量吞吐。

本文按[产品主线](2026-09-27-product-mainline-draft.md)和[场景 S0-S4](2026-09-28-network-scenario-walkthrough.md)解释需求；S5 指官方 relay 可禁用、自建或受支持扩展可替代，以及“资源许可先于质量”的共同约束。Rust 新开发、深入修改 iroh 内部、尽量保留 `Endpoint` / `Connection` / stream 用法是研究方向。MQTT/IRC 是消息型信令入口，不被伪装成数据报载体。ACL 设计暂停；成员证明、创世权限和服务访问规则不写死到连接库。

证据标记：**F** = 固定 1.2.0 源码或公开 API 的直接事实；**I** = 从这些事实推得的设计缺口/候选方案；**U** = 尚需实验或协议选型，不能当成已经实现。

## 1. 已有连接流程能省下什么

`Endpoint::connect_with_opts` 先 `resolve_remote`，后把目标身份交给 noq 发起 QUIC 握手；`resolve_remote` 只等**至少一个可能地址**，不等实际路径可达。没有选中路径时，Initial 发往 peer actor 已知的 IP、relay 或 custom 地址；此时尚无可运行 QNT 的 QUIC 连接。入站/出站最终由同一端点认证和 `Connection` API 承载。见 [connect_with_opts](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/endpoint.rs#L1100)、[RemotePathState::resolve_remote](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/socket/remote_map/remote_state/path_state.rs#L161)、[Initial 发送](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/socket/remote_map/remote_state.rs#L788)。**F**

`RemoteMap` 按已知 `EndpointId` 建立 `RemoteStateActor`；一个 actor 可管理该 peer 的多条 QUIC 连接。连接注册后，它接收路径/候选事件、更新 QNT 地址、触发打洞并对各连接打开选中路径。QNT 不要求首条连接走 relay，前提是已有一条可用 QUIC 路径。noq 已负责 QUIC/TLS、流、路径验证、丢包和拥塞处理；原生 relay client 有自己的连接与重试 actor。这些是 fork 应保留的实质能力，不需要再在上层包一套连接编排器。见 [RemoteMap::resolve_remote](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/socket/remote_map.rs#L311)、[AddConnection](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/socket/remote_map/remote_state.rs#L382)、[QNT 触发](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/socket/remote_map/remote_state.rs#L500)、[路径应用](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/socket/remote_map/remote_state.rs#L680)。**F**

`AddressLookup::resolve(endpoint_id)` 是**已知身份的地址查询**；多个服务并行，先有地址先返回。lookup `Item` 的 `last_updated` 字段在 1.2.0 注释中明确尚未使用。它省去多地址查询的基础并发，但不负责未知成员发现、持久成功路线排序、双方协商或成员证明。见 [AddressLookup trait](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/address_lookup.rs#L317)、[Item](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/address_lookup.rs#L362)、[服务合并](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/address_lookup.rs#L544)。**F/I**

**S2 职责边界。** iroh 的 peer actor 能管理某对端点的多连接和路径，却不是群体拓扑管理、后台有限预算互联或持久记录复制器。A-B、B-C 已连时，A 可借这些连接转交信令/记录，是 miopunch 的上层协议与持久同步职责；原作者离线仍补齐记录须靠可验证记录存储/复制（如待评估的 p2panda），不能归功于 iroh。连接库可在内部根据产品提供的目标与预算主动改善互联，但不应据此要求全对全常驻。**F/I**

**S4 职责边界。** `AddressLookup::resolve` 以已知 `EndpointId` 为入参，[lookup Item](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/address_lookup.rs#L362) 载 `EndpointInfo` 和来源标记，可含应用 `UserData`，但接口不会主动发现本地名单未知的合法 C，也没有成员资格验证语义。产品须提供候选发现与可验证成员材料；连接库须允许把发现的候选纳入同一建连流程，握手身份与候选/成员证明对应。证明可按选定成熟机制在 QUIC 握手前、中或经受限连接后交换，不在此冻结顺序；先全网同步才准建连会堵死恢复。**F/I/U**

## 3. 不能仅靠配置解决的内部细节

1. **资源硬闸有多处入口。** `RelayMap` 用于本机 home relay 候选及配置；它**不是远端 URL 白名单**。[`RelaySender::is_valid_send_addr`](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/socket/transports/relay.rs#L282) 对 URL 返回 `true`；[`RelayActor::active_relay_handle`](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/socket/transports/relay/actor.rs#L1321) 会按显式/lookup 得到的 URL 新建 client，而 `RelayMap::get` 在该处只获取 auth token。故 `Minimal + 自建 RelayMap` 仅避免默认官方发布、lookup 和本机 home 选择；如果原生 relay transport 仍开启，来自显式 `EndpointAddr`、受允许 lookup、peer 交换或 actor 旧缓存的官方 URL 还须统一过滤，并在最终发送/建 client 处拒绝。完全禁用所有原生 relay 可用现成 `RelayMode::Disabled`，但那不能同时保留自建原生 relay。官方 relay 与官方地址查询是两个独立资源作用域。**F/I**
2. **若未来支持运行时禁用，另有撤销工作。** [`remove_relay`](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/socket.rs#L1244) 只改 map 并通知重新地址观察，[处理函数](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/socket.rs#L1758) 没有清除远端路径或关闭 active relay actor；[`RemotePathState::prune_paths`](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/socket/remote_map/remote_state/path_state.rs#L210) 不剪 relay。已有选中/备用路径和 client 生命周期也须处理。当前产品没有确认热修改，故不把这一整套清理列为启动期必做。**F/I**
3. **无 relay 时的地址观察耦合。** [`DirectAddrUpdateState::run`](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/socket.rs#L778) 在 `RelayMap` 空时提前返回，连后续 `port_mapper.procure_mapping()` 都跳过；已有 [`add_external_addr`](https://docs.rs/iroh/1.2.0/iroh/endpoint/struct.Endpoint.html#method.add_external_addr) 可注入可信外部 UDP 地址。S1 若脱离原生 relay，连接库仍要从获准观察者取得与**同一 UDP socket**相关且有期限的候选，并经现有 direct address watcher/QNT 路径更新。MQTT 的 TCP 出口地址不能充当 UDP 映射。候选观察来源、NAT 目标依赖与过期规则要验证。**F/I/U**
4. **路径质量已有公开扩展口，但内部仍有固定假设。** `Builder::path_selector` 可传 `Arc<dyn PathSelector>`；[`PathSelectionContext`](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/socket/remote_map/remote_state.rs#L1284) 提供开放路径和 noq path stats，API gated by `unstable-custom-transports`。因此“质量优先”本身可先在 selector 适配；但默认 selector 把所有 custom 路径当 primary，低 RTT 不等于高吞吐；[`check_connections`](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/socket/remote_map/remote_state.rs#L751) 仍只把 RTT ≤10ms 的 **IP** 算足够好，会继续推动 UDP QNT；[`notify_quic_network_change`](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/socket.rs#L1697) 把 relay 视为可恢复、所有 custom 视为不可恢复。新 peer relay/TCP 需真实路径属性、探测预算和恢复能力，不能仅替换 selector。**F/I**
5. **普通 peer relay 与 TCP 不是原生 relay 的自动副产品。** 原生 relay actor 连接的是 `RelayUrl` 指向的 relay 服务，不会自动把 A-B 与 B-C 两条成员连接变成 A-C 电路。若经普通 B 转发 A-C QUIC 包，需定义电路建立/准入（业务数据中继须启用）、路由寿命、防环、队列和资源预算，并让 B 只见必要转发元数据，不拿到 A-C 业务明文。iroh 的 [`CustomTransport` / `CustomEndpoint` / `CustomSender`](https://github.com/n0-computer/iroh/blob/17c0612f80f78f5288e97b818b1360ae6ea0a51a/iroh/src/socket/transports/custom.rs#L20) 是包收发接口；TCP/TLS/WS 承载需要分帧、背压、重连及打洞协调，不能把任意 TCP stream 直接当 `Connection`。作为 custom 包载体进入现有 `MappedAddrs` / `open_path_on_conn`，架构上可归入**同一 QUIC 连接**，而非独立 dial；实际跨载体保留 stream 及拥塞、MTU 行为必须实验。是否需要改 noq，要等这一步证明其现有路径 API 不够。**F/I/U**

按实施归属收束：**现成复用**是 Endpoint/Connection/stream、已知身份 lookup、原生 relay、QUIC 后 QNT 与多路径；**配置或适配**是 Minimal preset、自建资源、`AddressLookup`、`PathSelector` 和 `CustomTransport` 入口；**确定的 iroh fork 工作**是前 QUIC 双端协商及同 socket 探测衔接、允许自建 relay 时的候选过滤/最终许可闸、无 relay 的地址观察与新路径恢复状态；**待 spike** 是 TCP/普通 peer relay 能否按预期维持同一 QUIC 连接及是否需要 noq 变更。上述“确定”指实现目标要求的功能缺口，不预设具体 Rust 模块边界。

## 4. 最有价值的结论与最小实验

1. **先做单次 `connect` 的两条起始路径纵切。** 同一个公开调用分别经获准原生 relay 和仅消息信令协调的 UDP 直连建连，接收侧仍 `accept`，最终得到同类 `Connection`。观测“线索、协商、探测、QUIC 握手、路径验证”各阶段，并加入同时发起、重复递送、取消。它最直接检验前 QUIC 状态能否融入 peer actor，而不把上层变成编排者。
2. **做官方资源硬禁用的负向实验。** 保留自建 relay transport，同时分别从显式地址、lookup、peer 转交喂入官方 relay URL；抓出站证实没有连接/包流向官方 URL，且自建 relay 仍可用。单独检查官方 DNS/Pkarr 是否启用；这两个作用域不能混称“关官方 relay”。
3. **做同一连接的 B→D/直连切换。** 在长 stream 中断开 B，确认 `stable_id`、stream 内容和路径事件；有路径时继续，无路径但连接未超时则经旁路协调新路径，超时后明确失败。优先用测试传输/可控网络故障，不以重新拨号冒充成功。
4. **做 custom TCP/peer relay 的窄幅可行性实验。** 先让包载体进入一个已存在的 A-C QUIC connection 并切换，检查 MTU、背压、外层 TCP 队头阻塞和超时；再决定是否改 noq。没有这项证据，不声称 TCP 或 peer relay 已达到产品性能目标。
5. **做无原生 relay 的候选来源实验。** 固定 UDP socket，经自建/普通观察者更新外部地址，在 relay map 为空时验证端口映射与候选更新，检查地址过期及目的相关 NAT。它决定地址观察需要 fork 多深，不以一次 STUN 返回值证明普遍可达。

这些都是拟议的最小验证，不是本报告已执行的测试。当前最可复用的是 iroh 的认证 QUIC、原生 relay、连接后 QNT 和多路径；确定的深 fork 缺口是前 QUIC 消息协商/UDP 探测衔接、获准资源硬闸及无 relay 的观察与恢复状态。持久同步和成员授权证明由产品/同步层给出依据，连接库只消费必要身份与策略结果。
