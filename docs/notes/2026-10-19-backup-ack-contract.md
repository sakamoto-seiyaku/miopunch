# Backup ACK 经实测改为显式 probe 行为

2026-10-19，[MIOPUNCH-102](http://192.168.4.22:2080/work/projects/aa58cd82-2afc-404b-a097-58ef553c7ca4/issues/45c5771d-0337-44b3-97cb-89e788874db7)
按 [ADR 0012](../adr/0012-preserve-library-contracts-and-defaults.md) 分类既有
Backup ACK 改动：保留显式探测能力，恢复普通 Noq 调用者的原版默认调度。
该选择依据普通消费者的实际反例；没有将 demo 所需行为认定为通用缺陷修复。

## 采用的契约

普通连接及原有 ping/ping_path 保留原版跨路径 ACK 调度。调用 fork 已有的
start_path_probe 或 Path::start_probe，才选择当前本地绑定的 Backup ACK
优先经该路径返回。它只影响被选择的路径，不改变其他 Backup 的默认调度。
这项偏好持续到绑定替换、关闭，或本地 IP 被清空、改变；保持相同地址的
网络变化通知保留已有选择。地址连续未知的恢复通知也会清除选择，不能把
两个未知值当作同一已知绑定。新建及远端迁移构造的绑定从普通策略开始。

双方需要各自在本地选择，才能在仍保留 Available 状态的主路径黑洞时，
取得双向的备路新鲜确认。Iroh 现有 Path::start_probe 和受限路径资格检查
继续使用原入口，无需新增端点配置或另一套生产接口。慢备路的本路径 ACK
可能增加确认延迟；这是显式选择的代价，不再由所有普通连接承担。

该选择不授予普通帧或数据路径权限。发送仍遵守原 ordinary-frame 条件，
收包仍在记录去重及 ACK 状态前丢弃不被允许的整个 STREAM 包。新鲜证明
继续使用已有认证 ACK、水位和绑定 generation；本项没有修改认证算法、
QUIC 帧、拥塞控制、丢失检测、连接生命周期或既有关闭调度。

## 形成选择的实测

首次生产修改前已固定普通 Noq 消费者。原版为 published Noq 1.3.0，保留
默认 features、原始锁文件及完整依赖行；fork 使用同一消费者源码和依赖
图，仅把 NoqProto 切换到本地 fork。两个自有 UDP 转发路径承载实际 TLS、
业务流和 ACK。客户端 A 为 Backup、B 为 Available；服务端优先 A，B 为
Backup。慢路场景只对 B 的返回方向增加 250 毫秒延迟。

| 实际业务确认 | 原版 | 修改前 fork | 最终普通默认 |
| --- | ---: | ---: | ---: |
| 健康多路径 | 约 1 ms，ACK 经 A | 约 1 ms，ACK 经 B | 约 1–2 ms，ACK 经 A |
| 慢 Backup 返回路径 | 约 1 ms | 约 253 ms | 约 1–2 ms |
| 慢 Backup 加一次实际 UDP 丢失 | 约 29 ms | 约 532 ms | 约 29 ms |

丢失用例确实丢弃一个客户端 B 路 UDP 包，观察到发送端 lost_packets 增加，
并验证全部业务内容、发送流的确认完成及后续关闭。这些是受控回环结果，
不是公网性能承诺。普通及显式探测的最终消费者均重复执行，原始回执、
实际 ACK carrier 和选中源码由[验收证据](../evidence/backup-ack-compatibility-2026-10-19/README.md)
保存。

主路径 A 黑洞而状态仍为 Available 时，原版普通场景等待 ACK 超时；恢复
A 后，原连接继续完成业务。最终普通默认保留这个边界。双方显式 probe
后，备路可以返回新鲜认证 ACK，同时排队的服务端普通 STREAM 不会进入
Backup。

未恢复的旧主路还会使原版及 fork 的对端关闭通知在两秒观察窗口内不可见；
显式 ACK 选择没有修复这一关闭路由边界。恢复或退休旧路径后的关闭，以及
实际维护流程的关闭和资源回收，单独验证，不能用“收到备路 ACK”代替。

## 回归边界

普通 ACK 路由用例先在修改前 fork 失败，再恢复为通过。额外覆盖单条备路
的选择不影响另一备路、旧 ACK 与已关闭路径拒绝、socket 绑定隔离、迁移、
恢复和关闭。

一个实际加密 STREAM/PING 包在 ordinary-frame gate 拒绝时，即使过了 ACK
期限也不能产生 ACK；资格允许后重播同一加密包仍能交付原内容并取得新鲜
确认，避免把丢弃的数据错误地当成已送达。

审查补出了原地修改本地 IP 时偏好未重置的问题。可恢复网络变化的回归在
修复前失败，修复后通过；相同绑定的通知保持选择，未知本地绑定要求重新
选择。另一个新增夹具最初把新本地 IP 注入普通服务器，被原有接口检查提前
拒绝，不能算产品反例。修正后从允许本地迁移的客户端方向验证真实加密包
和 ACK 路由，原始准备失败记录继续保留。

最终审阅另补出连续未知地址的边界。回归经公开恢复通知把客户端本地 IP
清空、启动显式 probe，再次通知地址仍未知，然后注入实际加密的 Backup
PING；修复前 ACK 仍走 Backup，修复后恢复跨路径 ACK。此用例与已知地址
不变时保留选择的用例共同限定重置条件。
