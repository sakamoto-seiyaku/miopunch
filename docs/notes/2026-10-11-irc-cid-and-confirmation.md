# IRC 握手：CID 池与受限确认的实测优化

本轮按“继续探究，要以实际收益为准”继续 M88，范围和结果记录于
[MIOPUNCH-89](http://192.168.4.22:2080/work/projects/aa58cd82-2afc-404b-a097-58ef553c7ca4/issues/f0f95306-bafe-4bae-9a21-8784b0c55d82)。
固定比较基线为 `05f99e3d078e17c69c53419faf681dec6cadec5a`。
Base64、完整 IRC 行容量、SAFERATE 和现有 QUIC 拥塞及重传算法沿用 M88。

## 保留的实现

Noq 新增可配置的每路径活动远端 CID 上限，支持 2–5，默认仍为 5。
接收和退休窗口按照实际广告上限检查；底层环形队列仍有五个槽位。
iroh 的通用 builder 只修改这一字段，保留调用者其他 QUIC 设置。
两端选择 2 时，七个未来路径的初始 CID 池由 35 个降到 14 个，基础路径
额外 CID 由 4 个降到 1 个；八个并发路径槽位、CID 轮换和路径恢复仍保留。
这描述初始分配量，不是把 frame 发送次数视为不同 CID 数量。

自动选择 2 的配置条件保持保守。Browser 必须只有实际可用的 IRC 联系能力，
没有 MQTT、relay、有效 RTC 或已安装的成员数据转发。Native 必须通过配置
启动、实际安装 IRC、没有安装 MQTT/RTC、UDP/TCP 被关闭，且成员数据转发
与获准数据 relay 均不可用。Native 自定义 builder 保留调用者的参数。
公网探针通过通用 API 显式配置初始自定义 IRC 端点为 2；MQTT 和重开的
成员端点保留默认 5。它验证该参数的收益与安全，不认证所有平台的默认配置。

新版 SDK 的已知受限准入请求合并旧一字节阶段接受与已有统一会话确认，
实际应用 stream 前由两个控制 stream 减为一个。Native 只在同一 builder
已安装 CoordinatorHook 时启用；Browser 请求等待已有统一确认完成。
严格封装、版本、用途、相反角色、能力/许可位、nonce、当前权限、原 TLS
对端、exporter 绑定和稳定会话身份继续检查。未批准请求保持受限 A，
没有普通业务 handle 或数据释放。成员秘密证明、成员阶段接受，以及单独
使用 AdmissionGate 的流程保留。双方应部署本轮相同协议实现；本轮按
ADR 0009 已接受的方向不增加旧 SDK 兼容分支。

## 测量解释

原始 Base64 基线两轮初次请求为 60.488 与 59.986 秒。仅缩减 CID 的
三轮完整公网故事为 35.400、48.080、48.105 秒，说明确有收益，也有明显
网络/确认前重复发送波动。初次请求仍通过正常 TLS、预期对端和严格 purpose2，
Native 保存真实的未批准请求；审批、材料保存、双方持久身份重开、获准 relay
成员业务 PING/PONG 和自然清理均执行。

合并版前三轮为 43.614、43.043、43.107 秒；收紧配置条件后的最终当前 SDK
为 43.081 秒，完整故事约 77.072 秒。最终请求相对两轮原始基线约快 28%，
不是时延保证。公网合并版与仅 CID 版的范围重叠，不能单凭这些结果隔离确认
合并的贡献，也不能把旧确认的约 22 秒直接声称为净节省。

最终公网 caller 和 attempt 都显式设置为 60 秒；assembly 8 秒、queue
30 秒、配置 fallback 600 毫秒继续沿用比较条件，双方实际 SAFERATE 生效。
这证明本组设置下的 60 秒 caller 成功，不是完整默认 IRC profile 的认证。
第一次 500 毫秒 WSS 观察仍为 false；再观察约 2 秒，所有关闭事件在销毁
context 前到达。Native 自然退出、驱动为零，未靠强制结束取得成功。

自有慢 IRC 对照共用同一固定镜像、TLS 设施和限速设置，按“仅 CID、合并、
合并、仅 CID”顺序运行，保持活动 CID 为 2、其余请求配置一致。历史构件
使用其自己的源码副本及图，不重新标为当前 SDK；只允许列明的源码差异。
首轮功能请求为 28.649 / 24.115 / 24.610 / 29.139 秒，但继承的 500 毫秒
观察没有捕获 WSS 的晚到关闭事件，所以整组回执保持失败，不算完整资格。
重跑只修改关闭事件观察器，四轮均完整合格：29.139 / 24.109 / 23.640 /
28.642 秒。仅 CID 平均 28.891 秒，合并后平均 23.875 秒，少 5.016 秒，
约快 17.4%。四轮最初的 500 毫秒观察都为 false；追加约 1.0–1.5 秒观察后，
所有 WSS 关闭事件在 context 销毁前到达。该结果证明这个自有慢设施对照
中的增益，不能将其百分比叠加为任意公网时延保证。

连接和 TLS/hooks/统一确认的计时范围包含彼此的阶段，不代表纯 TLS 时间。
旧 gate 快照在统一确认之前，新 gate 快照在统一确认之后，不能直接比较
这两个切点的流量。证据另外记录相同“完整初次请求返回”切点的 frame 与
datagram 统计。PTO 等重复发送仍在；本轮不修改重传算法，不声称所有发送
的路径 CID frame 都可以删除。

## 验证与审查

真实 SDK 回归先记录额外控制 stream 的红测，再验证只剩一个控制交换；
另外验证六种畸形确认/错误 nonce 在 handle 返回前被拒绝。最终 Native/WASM
所选构件和源码图经过构建前后核验，41 项 SDK 测试通过。Noq 的 432 项
测试包含两 CID 的轮换和八并发路径；最终重核验其 1780 个实际输入未变，
复用已执行的结果。Noq selector 的相对路径捕获曾需修正，原捕获明确不合格，
修正后的源码、原始 depfile 和图另行留存，没有把错误映射算成当前证明。

六项当前 SDK 自有设施回归通过：无效预算、2 秒 caller、闲置后的维护监听、
取消、禁用 IRC 无 I/O、MQTT 受限请求。独立 Standards 和 Spec 审查发现
初版自动 CID 适用条件过宽，已收紧并重新构建和执行当前 SDK；原发现和
最终报告均保留。共享 target、稳定 profile、固定锁图和所有实际构件副本
保留；只按审查清单清理重复/旧测试缓存。既有 234 份 WIP 保持原样。

公开证据采用标量和 hash 白名单，不发布身份、CID 内容、ciphertext、grant、
秘密或持久 store。详见
[实测证据](../evidence/irc-cid-confirmation-2026-10-11/README.md)。本轮结果不
替代 M84/M69 的实机平台矩阵或完整默认 profile 验证。
