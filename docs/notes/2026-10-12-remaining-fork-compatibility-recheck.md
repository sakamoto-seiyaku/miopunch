## 3. sync features 与 artifact 不是协议重写

**sync**：唯一正常依赖 manifest 差异是 `p2panda-store default-features=true → false`。原 store 默认 `sqlite,macros`，sync 自身 `default=[]` 不表示其 transitive store 默认为空。即使旧 native 调用方写了 `p2panda-sync default-features=false`，原 store 默认仍会开启，因此只增加一个 sync 默认 `native-store` feature 不能覆盖这类旧用法。[当前:71](../../vendor/p2panda-sync/Cargo.toml:71)、[原版:71](/tmp/miopunch-fork-audit-20261012/baselines/p2panda-sync/p2panda-sync-0.7.1/Cargo.toml:71)、[固定 store features:48](/home/js/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/p2panda-store-0.7.1/Cargo.toml:48)。

最贴近原 native 用法的候选是 common store traits-only，加 native target 的正常 store dependency 恢复原 defaults/明确 sqlite+macros；browser target 保 traits-only。需要界定 `wasm_browser` 的配置来源与 Cargo target cfg 可表达性，不能随手写 `not(wasm32)` 然后宣称只排除了 browser——WASI 也受影响。另一候选是 sync 默认 `native-store`，Browser 显式关闭；实施较直观，但必须公开上述旧 explicit-default-false 用户仍受影响的兼容边界。Cargo feature 是加法，不能“再加一个 wasm feature”取消另一路已启用的 SQLite；本次未做 feature graph 实证。[root manifest:50](../../Cargo.toml:50)、[browser manifest:19](../../browser-probe/Cargo.toml:19)、[sync dev/test_utils](../../vendor/p2panda-sync/Cargo.toml)。

sync Rust 实现与原始包逐文件一致：LogSync、manager、dedup、store traits 无算法变化。可仅整理 manifest，保 root/Browser replica 同步、完整 body 保存、验证/apply/replay/reopen，没理由另造兼容 wire 协议。[Native replica](../../src/offline_replica.rs)、[Browser replica](../../browser-probe/src/replica.rs)。

**artifact**：iroh/iroh-relay 从 lib+cdylib 改成 lib-only，是已确认产物差异，不是常规 Rust dependency 源码断点。**iroh-relay 的 bin 声明与 `src/main.rs` 均仍在，不能列成 relay CLI 被删。** 应保本仓库现有构建缓存/独立 JNI 生成规则，旧 cdylib 使用者如存在再评估独立产物入口；不机械恢复会覆盖共享缓存未哈希 DLL 的混合构件默认。[iroh manifest:102](../../vendor/iroh/Cargo.toml:102)、[relay manifest:110](../../vendor/iroh-relay/Cargo.toml:110)、[relay main](../../vendor/iroh-relay/src/main.rs)、[build-cache 原因:45](../agents/build-cache.md:45)。

Noq normalized manifest 仍引用已不存在的五个 examples、两个 tests、一个 bench；Noq-proto 引用已不存在的 send_buffer bench。dependency 使用与独立 all-targets/package 完整性应分开。候选是恢复固定版原文件或明确裁剪 distribution 并整理 manifest，不删除更多旧测试来冒充兼容通过。[Noq targets:118](../../vendor/noq/Cargo.toml:118)、[proto bench:105](../../vendor/noq-proto/Cargo.toml:105)。删除 vendored Cargo.lock 由根锁统一固定，属于独立构建入口差异，不代表运行算法删除。[固定来源 inventory](../evidence/fork-change-audit-2026-10-12/inventory.json)。

## 5. 最小 coherent 兼容分组

1. **普通/受限端点与 hooks/release 一组。** 原 plain Builder/Incoming/Accepting 与 early-data、旧 Accept/Reject hook 保留；新 endpoint/accepting 或等效能力隔离表达受限模式。此组同时覆盖 Router、IntoFuture、accept_with、endpoint 传递与 before_data_release，不能只加 try_into_0rtt 或恢复旧签名却留下受限 bypass。[当前 TLS 关闭条件:339](../../vendor/iroh/src/endpoint.rs:339)、[共同完成/释放:417](../../vendor/iroh/src/endpoint/connection.rs:417)、[hook 合成:205](../../vendor/iroh/src/endpoint/hooks.rs:205)、[已接受 ADR 0010](../adr/0010-preserve-upstream-early-data-interface.md)。Reject 优先、白名单交集、scope 冲突拒绝、申请受限、材料 durable 保存、原 M + fresh ACK + Ready/ACK、drop/cancel 关闭当前 pending M 都是 demo 不变约束。无需扩大为 TLS 算法或完整应用协议重写。
2. **auth 旧 error 与新 checked error 一组，独立。** 共享算法，只有 checked 入口携带 PolicyRejected；root AuthError 以及 pending-error 分类随 wrapper 映射调整。验收旧穷尽 match 与 checked 拒绝不入 graph。[root AuthError](../../src/management_auth.rs:42)、[management store](../../src/management_store.rs)。
3. **sync native/browser feature 图一组，独立。** 单独 native 旧 consumer（含 sync default=false）与 Browser traits-only 两条路径核对；不改 LogSync/管理记录算法。需要先确定 browser target/WASI 边界，然后再实施 manifest。
4. **默认资源与 resolving 策略一组小切片。** Portmapper、pkarr redirect、panda 缺 transport lookup 的旧默认分别有真实选择；在新/产品构造入口显式安装当前所需 policy，不能把整个产品资源规则塞进 raw 默认。三项内部独立，可逐项交付，不需要抽象成大兼容框架。
5. **选路作用域与底层 qualification/ACK 一组，后续单独收敛。** 旧 selector 回调域、raw filter 成本与 Backup ACK 默认变化一并审视；新 per-connection qualification 和 fresh probe 继续正确，Socket 不重新拆。ACK 是通用修复还是新模式行为尚待选择，不能先贴“纯 additive”标签。
6. **distribution/产物边界一组，按实际消费者。** 缺失 targets 可恢复 pin 源或明确裁剪；cdylib 是有理由的明确例外，现 Rust/native/Android 构建规则维持。不把主 demo 一次通过等同于 vendor package 完整。

这些组只有第一组必须一起设计才能消除源码 break 和安全 bypass；auth、sync、默认资源并不需要等一个全层重写。最终顺序由整体方案收敛，不在本笔记创建任务或实施。

验证也按组：旧 consumer 的原签名/穷尽 match/默认行为，严格 demo 的拒绝与保存重开，以及确实受影响的平台故事。主 demo 成功不能代替原 consumer 编译；旧兼容成功也不能代替未审批/撤销/early-handle/错误路径拒绝。此轮仅静态证据，尚未执行这些检查；未变的慢 NAT 或完整物理矩阵无需因为一个 error/manifest 切片自动重跑。此前两份 [iroh 评估](2026-10-12-iroh-upstream-interface-compatibility-feasibility.md) 与 [p2panda/demo 评估](2026-10-12-p2panda-and-demo-compatibility-feasibility.md)仍是历史研究参考，其中 socket 候选以 ADR 0011 与当前源码为准。
