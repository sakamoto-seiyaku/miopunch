# 外部参考项目

## 文档状态

- 本文档收束当前阶段已确认的外部参考项目。
- 这些项目用于吸收工程经验，不代表整体照搬。
- 是否进入主线仍以实验结果、测试证据和后续 OpenSpec change 为准。

## 使用原则

- 优先借鉴经真实网络验证过的工程处理，而不是只抄 `RFC` 字面流程。
- 优先借鉴局部机制：candidate 模型、端口映射生命周期、双栈策略、观测输出、测试方法。
- 不因为参考项目能力更大，就提前引入本项目阶段外能力。
- 借鉴点与不借鉴点都要明确记录。

## 当前参考清单

### `frp`

- 主要用于 `P1`：`xtcp`、`pkg/nathole`、控制面与 P2P 数据面的行为基线。
- 后续阶段继续作为行为对照，但不是最终架构上限。

### `Tailscale`

- 主要用于 `P2`：`netcheck`、`portmapper`、endpoint / candidate 聚合、双栈探测、可观测性。
- 也可用于后续 `overlay / mesh` 与弱中心协调阶段参考。
- 借鉴重点是分层、生命周期和诊断设计，不照搬其完整产品架构与 relay 体系。

### `MiniUPnP`

- 主要用于 `P0 / P2`：`miniupnpd` 可作为 `UPnP + NAT-PMP + PCP` 的实验台基线，`miniupnpc` 可作为 helper 行为与错误码参考。
- 也可作为真实路由器行为偏差的对照样本。
- 优先借鉴其协议覆盖、错误码与实验环境价值，不直接引入 C 侧实现。

### `go-libp2p`

- 主要用于 `P2`：端口映射续租、失效恢复、网关重发现、多网关选择。
- 也可作为后续组网阶段的工程参考。
- 借鉴重点是生命周期与恢复策略，不照搬其整体 NAT 子系统接口。

### `goupnp`

- 主要用于 `P2` 的 Go 侧 `UPnP` 客户端实现基线。
- 需要注意其 `SSDP` 发现当前偏 `IPv4`，不能直接等价为完整双栈方案。
- 若采用，必须在外层补上选择、诊断与约束。

### `go-nat-pmp`

- 主要用于 `P2(v1)` 的 Go 侧 `NAT-PMP` 客户端实现基线（体量小、依赖面低）。
- 若采用，必须在外层补上超时、错误分类、诊断输出与候选裁剪。

### `pion/ice`

- 主要用于 `P2 / P3`：candidate 优先级、双栈 gather、地址过滤、路径切换与后续传输协商思路。
- 本项目不在当前阶段直接转向完整 `ICE`，但可吸收其 candidate 与双栈处理经验。

### `gonc`

- 主要作为工程启发式参考：多 `STUN` 归因、`NAT` 结果展示、端口规避、随机端口喷射、短 `TTL` 探测。
- 其中部分策略可进入实验分支验证。
- 不直接作为主线模板；其 `TCP punching`、`MQTT`、`relay`、代理等混合能力不应提前污染当前阶段边界。
